## 摘要
推箱子（Sokoban）是一种益智游戏，其中智能体在网格世界中把箱子推到未标记的目标位置，长期以来一直是一个基准规划问题。虽然很容易看出它与诸如使用自动叉车的仓储物流等实际应用之间的联系，但其多智能体版本仍发展不足。这是因为多智能体推箱子由于多智能体规划特有的因素而变得困难得多，例如随着智能体数量增长而迅速增大的分支因子，以及需要处理集成的任务分配与无碰撞路径寻找。在本文中，我们表明，通过利用多智能体路径寻找（MAPF）的最新进展，可以设计出可扩展的多智能体推箱子规划器。具体而言，我们的 Sokoban-LaCAM 能高效求解涉及数十个智能体和箱子的实例，同时保持完备性和最终最优性保证。这提供了证据，表明 MAPF 可以作为解决更广泛集体自动化问题的强大原语。

## Abstract
Sokoban, a puzzle game in which an agent pushes boxes onto unlabelled target locations in a grid world, is a long-standing benchmark planning problem. While it is easy to see the connection to practical applications such as warehouse logistics with autonomous forklifts, its multi-agent counterpart has remained underdeveloped. This is because Multi-Agent Sokoban is substantially more difficult due to factors specific to multi-agent planning, such as the rapidly growing branching factor as the number of agents grows and the need to handle integrated task assignment and collision-free pathfinding. In this paper, we show that a scalable planner for Multi-Agent Sokoban can be designed by leveraging recent advances in multi-agent pathfinding (MAPF). Specifically, our Sokoban-LaCAM efficiently solves instances involving tens of agents and boxes while preserving both completeness and eventual optimality guarantees. This provides evidence that MAPF can serve as a powerful primitive for solving broader collective automation problems.

- **整体含义**：论文并非只想解决 Sokoban，而是验证 **MAPF（多智能体路径寻找）算法能否作为更广泛集体自动化问题的通用搜索原语**。作者以 LaCAM 为基础，证明配置空间搜索可扩展到多智能体推箱子。

## 2. 方法论

### 2.1 核心思想
- 将 Multi-Agent Sokoban 建模为**配置空间搜索**问题：一个配置包含所有智能体和箱子的位置。
- 直接复用 LaCAM 的搜索框架，仅替换配置生成器为 **Sokoban-PIBT**，并加入任务分配启发式与剪枝规则。
- 保持**完备性**与**最终最优性**：LaCAM 穷举搜索配置空间，LaCAM* 可 anytime 收敛到 makespan 最优解。

### 2.2 问题定义与转移规则
- 实例：\(\langle G, A, B, T, Q_{\text{init}} \rangle\)，其中 \(G\) 为网格图，\(A\) 为智能体集合，\(B\) 为箱子集合，\(T\) 为目标位置集合，且 \(|B|=|T|\)。
- 配置 \(Q: A \cup B \mapsto V\) 是单射，保证任意对象不共享顶点。
- 合法转移条件：
  - 每个对象停留或移动到相邻顶点；
  - 无对象交换冲突；
  - 每个被推动的箱子必须有且仅有一个相邻智能体沿推动方向进入箱子原位置；
  - 一个智能体不能同时推两个箱子。
- 目标：最终所有目标顶点均被箱子占据；优化目标为最小化 makespan。

### 2.3 Sokoban-LaCAM 搜索框架
- 使用 LaCAM 的 Open 栈与 Explored 表，深度优先展开配置节点。
- 每个节点维护约束树队列，约束只规范**智能体动作**，箱子位置由智能体推动隐式决定。
- 通过增量式约束生成，避免显式枚举指数级后继配置，从而保持可扩展性与完备性。
- LaCAM* 通过搜索树重连实现 anytime 最终最优。

### 2.4 Sokoban-PIBT 配置生成器
- PIBT 根据每个智能体的偏好动作列表 \(\phi_i\) 在线性时间内合成无碰撞联合动作。
- 修改点：若智能体动作推动相邻箱子，则先模拟箱子移动，再检查箱-箱、箱-智能体碰撞；冲突动作被拒绝。
- Sokoban-PIBT 不保证总能生成可行配置，但失败由 LaCAM 继续搜索其他约束处理。

### 2.5 偏好构造：两阶段任务分配
1. **目标–箱子分配**：
   - 预计算 push-aware 距离 \(dist_p(t,v)\)：从每个目标反向 BFS，排除不可推位置。
   - 用 Ford–Fulkerson 增广路径求无权二分匹配，候选箱子按 push-aware 距离升序访问。
   - 再通过成对交换局部搜索，降低最大 push-aware 目标–箱子距离。
2. **智能体–站位分配**：
   - 根据目标–箱子分配确定“站位”集合 \(S\)：智能体可从该位置将箱子推向目标。
   - 过滤被其他箱子占据、下一箱位被占、或立即导致死锁的站位。
   - 采用约束贪心：每个智能体分配到最近未分配站位，且每个箱子最多一个智能体；随后成对交换优化。
3. **偏好生成规则**：
   - 若智能体已在站位上，优先执行推箱动作；
   - 若未到站位，按 \(dist_{G\setminus B}\) 到站位的距离升序排列动作；
   - 若未分配任务，按到最近站位的 \(dist_{G\setminus B}\) 升序，鼓励空闲智能体靠近未来任务。

### 2.6 搜索增强
- **随机重启**：以约 0.001 概率重新插入初始节点，逃逸搜索停滞。
- **可采纳启发式** \(h_{\text{T-B-A}}\)：结合目标–箱子 push-aware 距离与智能体–箱子距离下界：
  \[
  h_{\text{T-B-A}}(Q)=\max_{b_j\in B'}\left\{\min_{t\in T} dist_p(t,b_j)+\max\left(\min_{a_i\in A} dist_G(Q(a_i),b_j)-1,0\right)\right\}
  \]
- **搜索停滞检测**：若启发式值连续 64 次迭代不下降，触发随机重启。
- **死锁配置剪枝**：如四个箱子形成 2×2 块且不全是目标则剪枝；简单墙边箱/目标数量比较。
- **无标签重复检测**：智能体与箱子不可区分，比较位置集合而非对象身份，减少 Explored 状态数。
