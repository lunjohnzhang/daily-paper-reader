2DGS-Planner: Rasterization-based Path Planning
in 2D Gaussian Splatting Map
Jiwon Park1, Dong-Uk Seo2 and Hyun Myung2∗
Abstract— Gaussian splatting provides an explicit and effi-
ciently rasterizable scene representation for robot navigation.
However, individual Gaussian primitives may not reliably
represent obstacles as they are jointly optimized through alpha-
composited rendering from a finite set of reconstruction views.
We propose 2DGS-Planner, a path planner for ground robots
that reads planning-relevant geometry from a 2D Gaussian
splatting (2DGS) map through rasterization, rather than treat-
ing individual Gaussian primitives as obstacles. During offline
roadmap construction, multi-view attribution converts rendered
normal dispersion into structural scores for non-ground disks
supported by the reconstruction views. These scores guide
adaptive node sampling on the ground. Path-aligned ortho-
graphic queries validate candidate edges, while cylindrical
queries estimate local clearance fields that are cached on the
edges. During online planning, graph search initializes a route,
and path refinement reuses the cached fields while accounting
for the robot’s dimensions and ground constraints. Experiments
demonstrate improved roadmap connectivity, more accurate
clearance estimation, and higher planning success compared
with the tested baselines. These results support rasterization as
an effective geometric query interface for planning directly on
Gaussian maps. Code and data are available at https://2dgs-
planner.github.io/.
I. INTRODUCTION
Autonomous navigation requires spatial reasoning about
the environment to find safe and efficient paths. This rea-
soning is closely tied to how the environment is represented,
since planners interact with a map through the spatial queries
it can support efficiently. Occupancy grids enable graph-
based search through discrete occupancy lookups [1], while
signed distance fields provide differentiable distance queries
for gradient-based trajectory optimization [2], [3]. Point-
based geometric maps can be queried directly for collision
checking in sampling-based planning [4].
Recently, learned scene representations have been ex-
plored as environment maps for navigation [5]–[10]. Neural
Radiance Field (NeRF)-based approaches obtain collision
evidence directly from the learned density [5]. Other meth-
ods rely on rendered outputs for localization, image-goal
navigation, and traversability-aware planning [6], [7]. Both
approaches rely on evaluating an implicit field, which can be
computationally expensive for real-time planning.
Gaussian splatting (GS) [11] provides an explicit alterna-
tive, encoding scenes with Gaussian primitives and render-
ing images from arbitrary viewpoints through differentiable
rasterization. Existing GS-based planners generally treat the
primitives directly as obstacles or convert the map into
an intermediate geometric representation [8]–[10]. However,

Two properties of GS training motivate rasterization-based
geometric queries. First, the primitives are jointly optimized
through their contributions to alpha-composited renderings,
so the training objective constrains the composited geometry
rather than any individual primitive. This motivates querying
the composited geometry instead of treating primitives as
independent obstacles. Second, this supervision comes from
only a finite set of posed training views. Geometry outside
their observation support is therefore less constrained by
the training data. A planner should consider not only the
rendered surface geometry but also how well that surface
was observed during training.
We therefore propose 2DGS-Planner (Fig. 1), a ground-
robot path planner that treats rasterization as the geometric
query interface to a GS map. We build on 2D Gaussian
splatting (2DGS) [12], whose training aligns each disk with
the local surface through a normal consistency term, so that
surface normals become a rendered channel alongside depth
and alpha. The framework constructs a roadmap directly
from rasterized geometric queries without converting the
scene into an intermediate geometric representation. During
offline roadmap construction, multi-view attribution derives

The main contributions are as follows:
• We propose 2DGS-Planner, a ground-robot path planner
that queries 2DGS maps through rasterization without
an intermediate geometric representation.
• We introduce multi-view attribution that converts ren-
dered normal dispersion into structural scores for adap-
tive roadmap sampling.
• We formulate path-aligned orthographic and cylindri-
cal queries for edge validation and local clearance
estimation, with the clearance fields cached for path
refinement.
• We evaluate the proposed framework from geometric
reasoning to complete planning, including structural
attribution, clearance estimation, end-to-end path plan-
ning, and real-world robot experiments.
II. RELATED WORK
A. Rasterization-based Geometry in Gaussian Splatting
3D Gaussian splatting (3DGS) [11] represents a scene
with volumetric Gaussian primitives, while 2DGS [12] re-
places them with planar Gaussian disks to impose a surface-
oriented geometric representation. During rasterization, the
2DGS renderer computes ray–disk intersections and alpha-
composites the intersected disks along each ray, yielding
geometric quantities such as depth and surface normals
in 3D. Recent methods have increasingly exploited such
rasterized quantities as geometric signals. PGSR [13] renders
plane distances and normals for surface reconstruction, while
RaDe-GS [14] derives depth and surface normals directly
from rasterized 3D Gaussians. 3DGUT [15] further extends
Gaussian rasterization beyond standard pinhole projection
to support secondary rays. These methods use rasterization
primarily for rendering or reconstruction, while we use it
as a geometric query interface for path planning on a fixed
2DGS map.
B. Planning on Gaussian Splatting
GS-based motion planning and control differ in how they
obtain collision information. Splat-Nav [8] constructs safe
corridors from Gaussian ellipsoids, while SAFER-Splat [16]
formulates control barrier functions over the primitives.
SPLANNING [17] derives collision-probability bounds from
a normalized Gaussian field, and FOCI [18] optimizes tra-
jectories using overlap between Gaussian representations of
the robot and the scene, including trajectories for a legged
ground robot.

Rendering has also been used directly for collision avoid-

attached to a mobile manipulator and uses the resulting
distances for reactive control. Whereas ReMoSPLAT targets
reactive collision avoidance, we use rasterization for ground-
robot path planning on a fixed 2DGS map, with queries
organized around candidate ground motions to evaluate and
retain clearance for subsequent refinement.

IV. 2DGS-PLANNER
A. Problem Formulation and Overview
We plan for a ground robot on a static 2DGS map G
with reconstruction views V. The robot body is modeled as
a gravity-aligned ellipsoid with semi-axes (a, b, c), whose
center is maintained at a prescribed height h above the
supporting ground. Given start and goal locations on the
observed ground, we seek a connecting path that maintains
body clearance and ground support.
Fig. 3 summarizes the overall pipeline. The offline stage
constructs a roadmap H = (N, E) over candidate robot
positions. Multi-view attribution determines the sampling
density from rendered structural cues, while path-aligned
queries validate candidate edges and cache local clearance
on retained edges. During online planning, A∗initializes a
graph route, which is subsequently refined using the cached
clearance under body-clearance and ground constraints.
B. Map Preprocessing
Map preprocessing assigns semantic labels to the Gaussian
disks and aligns the reconstruction with gravity. Semantic
predictions from the reconstruction views are transferred to
the disks to identify ground regions. Ground-labeled disks
satisfying the orientation and height criteria form Ggrd ⊂G,
which defines the support surface for roadmap sampling and
path refinement. All subsequent planning is performed in the
gravity-aligned frame.

V. EXPERIMENTS
The experiments evaluate 2DGS-Planner at three levels:
roadmap construction, geometric query fidelity, and end-
to-end planning. Sec. V.D evaluates whether multi-view at-
tribution captures local structural complexity and improves
adaptive roadmap sampling. Sec. V.E evaluates the fidelity of
cached LCC clearance fields against a voxelized representa-
tion of the same rendered surfaces. Sec. V.F evaluates the re-
sulting end-to-end planning performance, including ablations
of adaptive sampling and LCC-based refinement. Sec. V.G
further illustrates how robot dimensions affect roadmap
connectivity and the resulting path through robot-specific or-
thographic footprint queries. Finally, Sec. V.H demonstrates
the planner on a physical humanoid robot.

B. Baselines
We compare against sampling-based planners and an
ESDF-based planner, all operating on the same 2DGS recon-
struction. Disk probabilistic roadmap (PRM) [25], RRT∗[4],
and Informed RRT∗[26] treat each Gaussian disk as an
obstacle truncated at its 1σ elliptical extent and evaluate
collisions using exact point-to-ellipse distances [27]. For
Disk PRM, we evaluate uniformly sampled roadmaps with
node budgets of 1k, 10k, and 60k to examine how increased
sampling affects roadmap construction cost and planning
performance. The ground-constrained ESDF baseline fuses
depth panoramas rendered from the reconstruction views
into an occupancy grid, performs A∗search on the resulting
distance field, and applies B-spline refinement. This base-
line evaluates planning through an intermediate volumetric
representation.
We evaluate uniform and adaptive roadmap sampling, each
with and without LCC-based refinement.
C. Implementation Details
The robot is modeled as a sphere throughout the exper-
iments, with radius r = 0.05 in scene units for the non-
metric Stonehenge map and r = 0.50m for the metric
Tokyo map. The anisotropic robot-body model of Sec. IV.A
is used only in the robot-size-aware planning experiment.
The roadmap uses node spacing ℓ∈[0.10, 0.25] in the
corresponding map units and a 64×128 cylindrical clearance
field per edge. For structural attribution, disks are retained
with support τS = 10−3 from at least Kmin = 3 views. Path
refinement uses a B-spline with 12 control points, maintains
the prescribed ride height, and revalidates the resulting
path using the orthographic query of Sec. IV.E. Semantic
labels are obtained with SegFormer-B5 [28] pretrained on
ADE20K [29] and grouped into task-relevant categories. All


experiments are conducted on an NVIDIA RTX 4090, an
Intel Core i9-10900K, and 94GB of RAM.
D. Structure-Aware Roadmap Construction
We evaluate whether rendered attribution captures local
scene structure well enough to serve as a sampling prior.
Fig. 6 compares rendered attribution (Sec. IV.C) with disk-
neighborhood scores on Stonehenge and Tokyo, taking
normal dispersion on the reference mesh as the measure of
local structural complexity. Spearman correlation ρs mea-
sures whether more complex regions receive higher scores,
and ROC-AUC measures how well the scores separate the
top 25% from the bottom 50% of reference dispersion.
At the disk level, the two scenes rank differently.
On Stonehenge, the finest voxel score correlates most
strongly with the exact mesh, indicating that individual disk
geometry represents local surface structure well in a synthetic
scene. On Tokyo, rendered attribution instead achieves the
highest ρs and ROC-AUC for both the full obstacle set and
the building subset, since deriving structure from surfaces
supported by visible disk contributions across views depends
less on noisy local geometry. The geometric scores also lose
consistency with the reference as the neighborhood scale
grows, revealing their sensitivity to the chosen spatial scale.
For node placement, the relevant quantity is the aggre-
gated score u(q) rather than individual disk accuracy. With
R = 3r, rendered attribution achieves the highest ρs and
ROC-AUC at Rref = r and 2r on both scenes, despite
its lower disk-level ranking on Stonehenge, so stronger
primitive-level agreement does not necessarily yield a better
sampling prior. The ranking again becomes less consistent
at larger scales, supporting rendered attribution as a local,
robot-scale structural signal. Whether this signal improves
planning is evaluated directly in Sec. V.F, where uniform and
attribution-guided sampling are compared under a matched
node budget.
E. Clearance Query Fidelity
We compare cached LCC fields with ESDFs constructed
from identical rendered 2DGS surface samples to iso-
late the effect of the clearance representation. The ex-
act Stonehenge mesh provides reference clearance, and
the evaluation focuses on configurations near the collision
boundary, where clearance estimation errors are most rele-
vant to planning decisions.
Fig. 7 shows that LCC yields lower clearance error and
fewer false-blocked configurations than the tested ESDFs,
better preserving free space supported by the reference
geometry. The higher false-blocked rates of the ESDFs are
consistent with volumetric occupancy fusion reducing the
represented free space, whereas LCC retains clearance in
path-aligned fields without additional volumetric discretiza-
tion.
These results indicate that LCC more faithfully preserves
the rendered surface information relevant to local feasibility
decisions. False-safe cases remain, however, so the estimated
clearance does not provide a collision-free guarantee. LCC

We evaluate end-to-end planning on 50 start–goal pairs per
scene in Stonehenge and Tokyo. For each start–goal pair,
we construct an evaluation-only reference path using scene-
specific reference geometry independently of the planner.

reports reference collision-pass counts and success weighted

ground-constrained ESDF baselines.

H. Real-World Humanoid Deployment
We demonstrate 2DGS-Planner on a humanoid robot
in a real-world environment (Fig. 12). The reconstructed
2DGS map is registered with the LiDAR map from FAST-
LIO2 [31], allowing the planned path to be transferred to
the robot. The robot tracks the path using a pure-pursuit
controller, demonstrating successful physical execution.

that directly queries planning-relevant geometry from 2DGS
