## 摘要
异构机器人团队能够通过融合多种具身形态在感知、移动与操作方面的互补能力，完成复杂且长时程的任务。然而，现有系统难以将执行过程中的修正保留为可复用经验，难以在空间和时间维度上维护与任务相关的上下文记忆以支持可靠交接，也难以显式表示结构化协作所需的机器人间依赖关系。为解决这些挑战，我们提出 InstAgent，一种面向异构机器人协作的递归自改进（RSI）智能体操作系统。InstAgent 将团队行为组织为智能体行为树（BTs），显式建模能力分配、机器人间依赖关系与交接检查。RSI 机制根据执行反馈更新这些协作程序，并保留成功的修订以供未来任务复用；同时，共享多模态时空记忆为规划与交接验证提供上下文。在 20 个真实世界多机器人任务上、使用三种高层模型的实验表明，其在任务成功率、首次尝试完成率和执行效率方面均取得一致提升。

## Abstract
Heterogeneous robot teams enable complex, long-horizon tasks by combining complementary sensing, mobility, and manipulation capabilities across multiple embodiments. Yet existing systems struggle to retain execution-time corrections as reusable experience, maintain task-relevant context memory across space and time for reliable handoffs, and explicitly represent the inter-robot dependencies required for structured collaboration. In order to address these challenges, we present InstAgent, a recursively self-improving (RSI) Agent Operating System for heterogeneous robot collaboration. InstAgent organizes team behaviors as agentic behavior trees (BTs) that explicitly model capability assignment, inter-robot dependencies and handoff checks. The RSI mechanism updates these collaboration programs from execution feedback and preserves successful revisions for reuse in future tasks, while shared multimodal spatio-temporal memory provides context for planning and handoff validation. Experiments on 20 real-world multi-robot tasks with three high-level models show consistent gains in task success, first-attempt completion, and execution efficiency.

## 1. 核心问题与研究动机

- **背景**：异构机器人团队（人形、四足、机械臂等）通过互补的感知、移动与操作能力，可完成单一具身难以胜任的长时程复杂任务。但这类任务远不只是“把技能分配给不同机器人”——机器人分布在不同地点与阶段，一个机器人的结果往往决定另一个能否继续。
- **现有 LLM 智能体系统的潜力**：将高层推理、异构技能调用、多模态感知与执行反馈闭环连接，适合流程无法事先完全规定的长时程协作。
- **仍存在的三个挑战**：
  1. **执行修正难以沉淀为可复用经验**：复杂物理任务很少一次规划成功，但执行中的修正往往是任务特定的，未以可继承、可继续改进的形式积累（Reflexion、Voyager、LRLL 等主要面向单智能体/单机器人技能）。
  2. **长时程协作缺乏持久时空上下文**：现有记忆系统支持空间/时间检索，但历史观测尚未与当前物理检查（交接验证）打通。
  3. **异构机器人被当作扁平技能集合**：缺少显式的机器人间依赖、交接条件与恢复逻辑，可靠性不足。
- **整体含义**：论文主张把“协作程序”本身作为可自我改进的对象（Structured-Program RSI），并与“经验文档式”RSI（Experience-Context RSI）结合，形成一个可继承、可验证、可回写的闭环操作系统。

## 2. 方法论

### 2.1 核心思想

- InstAgent 是一个基于 **ROS 2** 的智能体操作系统，把团队行为表示为**可执行行为树（BT）程序**，该程序可落地到共享环境上下文、在执行中被验证、并通过积累经验自我改进。
- 闭环为：**组合（Compose）→ 执行（Execute）→ 验证（Verify）→ 修订（Revise）→ 复用（Reuse）**，由四个组件支撑：Skill BTs、HeteroComposer、Collab-RSI、SMAR-T。

### 2.2 关键技术细节

- **Skill BTs（原子技能 → 可执行子树）**
  - 技能分共享模块（导航、感知）与机器人模块（运动、语音交互、操作）。
  - 每次技能调用被封装为**只含一个 Action 节点的最小 BT**（`skill` 字段标识 `module/skill`，`args` 携带参数），由确定性 wrapper 构造，并与一条“技能经验”文档链接。
  - MLLM 读取功能描述、接口定义、调用上下文与使用条件，转为 RSI 库统一表示；执行前校验 BT 格式、接口存在性、参数与 schema 一致性（运行时参数在解析后再校验）。

- **HeteroComposer（协作 BT 构造）**
  - 从经验文档库 `D_k` 检索候选文档，由 MLLM 依据目标与适用范围筛选，再取出关联子树 `T_k[ℓ(d)]`，构成经验集合 `E_k`。
  - 以“优先复用已有程序结构、未覆盖步骤用原子技能补齐”的方式构造完整协作 BT；按可用能力集 `S_k` 选择机器人/模块并绑定任务相关参数。
  - 跨机器人协调通过 BT 中的**序列、条件、恢复分支**表达，后继动作在前置条件满足后即可启动。

- **Collab-RSI（程序级递归自改进）**
  - 当继承的协作 BT 出现**交接失败、依赖未满足、恢复流程不足**时，智能体结合当前程序、任务目标、观测与相关经验定位受影响的协调步骤。
  - 修订可在两个层面发生：① 修改复用子树的**内部结构**（如增加结果检查）；② 修改子树之间的**关系**（动作分配、交接条件、跨机器人恢复路径）。
  - 候选程序经结构与技能接口检查后**重新执行验证**交接条件与任务结果；通过后写成“BT 结构 + 经验文档”的链接对（文档记录任务目标、所需能力与机器人角色、适用条件、失败上下文、修订理由）。
  - 由多个已有子树组合而成的已验证程序会作为**新的经验条目整体存储**，使“组合本身”也可检索复用；失败记录保留为诊断上下文。
  - 算法 1 流程：观测 → 选择经验 → 组合并检查 → 循环 {执行并验证 → 成功/预算耗尽/终态则跳出 → 确认可安全停止 → 修订并检查（最多 `J_max=3` 个候选）→ 重建并加完成检查，恢复预算 `B←B−1`} → 若写回标志 `w=1` 则更新经验库。

- **SMAR-T（共享多模态时空记忆 + 智能体驱动检索）**
  - 记忆条目 `m_i` 包含：图像 `I_i`、VLM 生成描述 `c_i`、视觉嵌入 `z^v_i`、文本嵌入 `z^c_i`、机器人在共享地图中的位姿 `p_i=(x_i,R_i)`、时间戳 `t_i`、来源机器人 `r_i`。
  - 检索工具三类：**位置**（按欧氏距离 `‖x_i−x̂‖₂` 排序）、**时间**（按 `|Δt_i−t̂|` 排序）、**语义**（先视觉相似度召回至多 10 帧，再用描述重排：`s_i=(1−λ)·ṽ_i+λ·ũ_i`，`λ=0.15`，返回至多 5 个候选）。
  - 智能体分解请求的语义/空间/时间约束，选择只读工具与搜索域 `U⊆H`，每次调用后联合评估图像、描述与元数据；**排序本身不等于满足约束**，冲突/缺字段/指代不明则继续检索；每次真实查询最多 10 次工具调用，证据不足则报告并请求新观测。

## 3. 实验设计

- **真实机器人平台**：G1（人形，交互与引导）、Go2（四足，导航与运输）、ALOHA（操作与装载）；共享导航与感知模块返回状态与执行反馈。
- **任务场景**：**20 个真实世界异构多机器人任务**，涉及能力分配与机器人间交接；重复出现的协作结构在物体、位置、目标上变化，用于测试子树复用与适配。
- **扰动类型**：到达误差过大、导航与加载失败、用户临时更改目的地。
- **成功判据**：相对移动误差 ≤0.10 m、转向 ≤10°；工作站导航需模块成功返回且人工确认到达误差 ≤0.5 m；所有物理与交互后置条件均需验证。
- **恢复预算**：每任务最多 5 次失败触发的恢复/重试；每个失败片段额外允许 3 个候选修订（被拒候选只消耗候选次数，不消耗执行恢复预算）。
- **对比配置（4 种）**：
  - **Simple CoT**：文本计划直接调用技能，无 BT；
  - **BT Recovery (E0)**：仅用注册原子技能构建 BT，无跨任务子树检索；
  - **Fixed-Experience BT (E1)**：额外检索已有子树并保持其可执行版本不变；
  - **Full InstAgent (E2)**：与 E1 同起点，但用匹配的历史反馈与案例进行修订、验证并保留。
  - 三个高层模型：**GPT-5.6 Sol、DeepSeek-V4-Pro、Qwen3.8-27B**；每个模型独立经验库，E1/E2 快照在评测前冻结，任务内修补不回写。
- **指标**：任务成功率 SR、首次尝试成功率 FSR（无失败触发恢复/重试）、初始 BT 逻辑一致性 LC（前置条件尊重的执行序判据）、平均恢复次数 R̄。
- **记忆 benchmark**：**RAVEN-QA**（RealWorld、Habitat-Sim、IRS、IRS-hard 四个子集），对比 **RAVEN、ReMEmbR、Ours、Ours w/o Agent**（去掉智能体、直接返回 Top-1），统一使用 QQMM-v2 嵌入与 Gemini-2.5-Flash。
- **统计检验**：E0 与 E2 在任务实例层面用 McNemar 检验（成功率）与 Wilcoxon 符号秩检验（恢复次数），三个模型均 p<0.05。
