## 摘要
视觉语言动作（VLA）模型被设计为通用机器人模型，可跨具身形态、任务和环境部署。然而，它们与其他机器人和人类协作的能力仍未得到充分探索。在本工作中，我们提出一个框架，可在无需人类遥操作的情况下，自动生成用于去中心化 VLA 训练的多机器人协作数据。我们的框架首先利用去中心化协作规划方法，以可执行函数的形式生成多机器人协作机器人计划。随后，我们利用该协作计划生成协作演示数据，以去中心化方式微调 VLA 模型。我们表明，我们的方法所生成的演示数据在用于微调 VLA 模型以完成去中心化协作任务时，其任务性能与使用人类遥操作协作数据微调的 VLA 模型相当。

## Abstract
Visual Language Action (VLA) models are designed to be generalist robot models that can be implemented across embodiments, tasks and environments. However, their ability to collaborate with other robots and humans remains underexplored. In this work, we propose a framework to automate the generation of multi-robot collaborative data for decentralized VLA training without requiring human teleoperation. Our framework first utilizes a decentralized collaborative planning approach to generate multi-robot collaborative robot plans in the form of an executable function. We then utilize the collaborative plan to produce collaborative demonstration data to finetune VLA models in a decentralized manner. We show that our approach produces demonstration data that when used to finetune VLA models on decentralized collaboration tasks matches the task performance of VLA models finetuned on human-teleoperated collaborative data.

## 1. 核心问题与研究背景

- **VLA 模型的协作能力缺口**：视觉-语言-动作（VLA）模型（OpenVLA、π0.5、SmolVLA 等）在跨本体、跨任务泛化上表现突出，但其**与其他机器人或人类协作**的能力仍缺乏系统研究。主流预训练数据（DROID、Open X-Embodiment 等）几乎全部来自**非协作的单机器人演示**，模型因而学不到"等待同伴完成子任务"这类协调信号。
- **单机器人微调不足以支撑协作**：论文明确指出并实验验证，即使在与任务相关的单机器人演示上做监督微调，VLA 在协作任务中仍会与同伴发生冲突（如两臂同时伸向柜子、堆叠时在中央相撞）。
- **协作数据采集的瓶颈**：多机器人同步协作数据需要为**每个额外机器人配备额外遥操作员**，且许多低成本平台（如 SO-101）根本缺乏多机遥操作接口，导致协作数据难以规模化获取。
- **关键洞察**：协作演示的本质是**子任务排序的条件依赖**——某个机器人的技能必须以其同伴的子任务成功执行及环境状态为前提（例：右臂只有在柜门被打开后才能放入方块）。因此，只要能生成满足此类条件约束的可执行计划，就能自动合成协作数据。
- **整体含义**：论文试图建立一条"**无需多机器人人类遥操作**"的协作数据自动生产线，使去中心化 VLA 训练在人机/多机协作场景下可行、可扩展。

## 2. 方法论

### 2.1 核心思想
将协作任务计划表示为**可执行的 Python 函数**，由两个 VLM agent（actor/critic）通过**去中心化协作蒙特卡洛树搜索（MCTS）**迭代生成与精炼；再用该函数驱动机器人执行、配合人类验证器筛选成功轨迹，产出协作演示数据，最后**各机器人独立（去中心化）微调自己的 VLA**。

### 2.2 协作计划生成模块（IV-A）
- **输入**：俯视相机观测、自然语言协作任务提示 τ、各机器人可用技能集合 S = S₁ ∪ … ∪ S_N（允许技能重叠与独有技能）。
- **去中心化 agent 结构**：每个机器人对应一个 VLM agent，一个担任 **actor**（提议计划），一个担任 **critic**（评分并给出针对性反馈）。初始提议 + 批评构成搜索树的根节点 p₀。
- **代码化计划的三点必备特征**：(i) 识别子任务前置条件；(ii) 子任务分配；(iii) 子任务调度以协调整体任务。
- **选择代码形式的两个动机**：① LLM/VLM 已被证明能生成连接环境输入与机器人技能的函数（CaP、ProgPrompt）；② 代码式计划天然支持多机器人**去中心化并行执行**。
- **MCTS 四步流程**：
  1. **Selection**：从根节点按 UCT 策略下行至叶节点，
     `UCT(cᵢ) = V(cᵢ) + w·√(ln N(pᵢ) / N(cᵢ))`，其中 N 为访问次数、V 为回传价值、w 为探索系数、pᵢ 为父节点。
  2. **Expansion**：扩展 n 个新子节点，每个子节点的计划是对父节点计划依据其批评意见的改进版本。
  3. **Evaluation**：critic 按三项标准各打 1–5 分（满分 15）：
     - *Progress Score*：计划对任务推进的有效性；
     - *Distribution Score*：子任务是否分配给合适的机器人；
     - *Condition Check Score*：是否利用环境反馈检查子任务前置条件。
  4. **Backpropagation**：`N′(cᵢ) ← N(cᵢ)+1`；`V′(cᵢ) ← (V(cᵢ)N(cᵢ)+r) / N′(cᵢ)`，沿路径更新至根。
- **终止与选优**：达到最大深度 d_max 时终止；分数超过阈值 r_thres 的节点视为"已解决"，取**已解决节点中价值最高者**为最终计划；若无已解决节点，则回退到回传价值最高的节点。

### 2.3 任务执行模块（IV-B）
- **语义层**：计划通过 VLM 查询俯视相机与各腕部相机图像，判断前置条件（如"黄色方块是否已在中央区域""柜门是否打开"）。
- **技能层**：感知模块用 **混合 blob 检测 + YOLOv8**（俯视深度相机）获得粗略物体坐标 → **IK 求解器（Placo）** 生成轨迹 → **腕部相机**获取精确抓取坐标。

### 2.4 协作数据生成（IV-C）
- 引入**人类作为任务验证器**，逐条判定 episode 是否成功；仅成功轨迹进入数据集 D_task。
- 明确选择人类验证而非 VLM 验证，理由是**规避 VLM 幻觉造成的假阳性轨迹污染数据集**。

### 2.5 去中心化 VLA 微调（IV-D）
- 将 D_task 拆分为各机器人专属数据流 D^n_task：本机器人关节状态 + 腕部相机流 + **共享**的俯视立体相机流。
- 各机器人 VLA **独立 SFT**，训练与执行阶段均不交换信息，只能通过动作隐式协调。
- **两种数据配方**：
  - **VLA_Co²Gen**：仅用 D_task；
  - **VLA_Co²Gen+SA**：D_task 与单臂人类演示混合，兼顾轨迹多样性与协作协调信号。
