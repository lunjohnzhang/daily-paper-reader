## ABSTRACT 

Embodied agents are increasingly capable of perceiving, planning, and acting au-tonomously in dynamic environments, demonstrating strong performance on com-plex cooperative tasks. Recent advances typically assume that cooperative tasks are known in advance. In real-world applications, however, hidden-cooperation tasks are more common: the need for cooperation only becomes apparent after an agent observes and interacts with task-related targets. In this paper, we first present HiddenCoop, a benchmark for effectively evaluating agent cooperation in hidden-cooperation tasks. We further propose Discovery-Probability Graph Plan-ning (DPGP), a method for enabling effective agent cooperation in such tasks. At the core of DPGP is a discovery-probability graph that encodes the probabil-ity distribution over the number and locations of task-related targets, facilitating effective and efficient information exchange among agents. A search algorithm is then used to derive action plans that minimize expected costs. Experiments show that DPGP achieves cooperative-task success rates of 99.3% on C-WAH and 58.3% on TDW-MAT, surpassing all compared baselines, while also reducing overall embodied execution time and substantially lowering LLM token usage. Our code is available at https://github.com/hnu-vis/DPGP .

## 1 INTRODUCTION 

Embodied agents show a steadily increasing capacity to perceive and interact with their environ-ments in human-like ways, while autonomously handling planning, decision-making, and action ex-ecution (ichter et al., 2023; Huang et al., 2023). These advances have generated considerable interest in such agents, particularly for tasks requiring cooperative execution in dynamic environments (Seo et al., 2026). Consider two household agents rearranging a home: each may search different rooms and transport objects individually, yet through interaction they discover that some objects require both agents. Such tasks, whose collaborative requirements must be discovered rather than specified in advance, pose a significant challenge to agent cooperation planning : the agents must share newly acquired evidence, coordinate a rendezvous, and revise the allocation of the remaining work. To tackle the challenges in agent cooperation planning, many methods have been proposed (Zhang et al., 2024; Liu et al., 2025; Zu et al., 2025; Seo et al., 2025; Jain et al., 2020; Kang et al., 2026). Early studies have primarily focused on Cooperation-Optional Tasks (Figure 1(a)), in which each task can be handled independently by a single agent, but involving multiple agents can further im-prove results through parallel exploration and task allocation (Zhang et al., 2024; Chang et al., 2025; Liu et al., 2025; Zu et al., 2025; Seo et al., 2025). However, such methods typically execute a task immediately upon discovering it, without considering whether to recruit other agents for joint exe-cution. More recent work has begun to investigate Visible-Cooperation Tasks (Figure 1(b)), where certain tasks inherently demand multi-agent cooperation (Jain et al., 2020; Kang et al., 2026; Mandi et al., 2024; Nayak et al., 2024). However, these methods generally assume that these cooperation requirements are known in advance. In practice, Hidden-Cooperation Tasks (Figure 1(c)) are more

This complex process reveals a critical yet underexplored problem: how to evaluate and enable effective agent cooperation in hidden-cooperation tasks when cooperation requirements must be discovered by the agents? 

In this paper, we introduce HiddenCoop, a benchmark for evaluating agent cooperation in hidden-cooperation tasks, and Discovery-Probability Graph Planning (DPGP), a method for enabling effec-tive agent cooperation in such tasks. HiddenCoop is built on C-WAH and TDW-MAT (Zhang et al., 2024) and includes both ordinary and cooperative household tasks. Cooperative tasks can only be completed by two agents, a requirement that remains unknown to the agents until they attempt them. To model the uncertainty during discovering and completing these cooperative tasks, DPGP builds its core around a discovery-probability graph. This graph encodes, for a given cooperative task, the probability distribution over the number of task-related targets and their locations. As discoveries unfold, the graph is updated dynamically and shared among the agents, enabling precise informa-tion sharing and efficient transmission. Based on this graph, a search algorithm is applied to find the action plans that minimize the expected costs. Experiments show that DPGP achieves cooperative-task success rates of 99.3% on C-WAH and 58.3% on TDW-MAT, exceeding all compared baselines. It also achieves lower overall embodied execution time and substantially lower LLM token usage compared to baselines. In summary, our contributions are threefold: • A new benchmark, HiddenCoop , for evaluating agent cooperation in hidden-cooperation tasks. • A Discovery-Probability Graph Planning method for enabling effective agent cooperation in hidden-cooperation tasks. • A series of experimental results demonstrating the effectiveness and efficiency of our method. 

## 2 RELATED WORK 

2.1 EMBODIED MULTI -A GENT BENCHMARKS 

Tasks with individually executable subgoals. C-WAH and TDW-MAT study household explo-ration, information sharing, and task allocation under partial observability; PARTNR additionally 2introduces spatial, temporal, and capability constraints (Zhang et al., 2024; Chang et al., 2025). In these settings, an appropriately capable agent can execute each object-handling operation with-out mandatory joint handling of the same object. HiddenCoop retains household exploration and multiple goals while introducing object-handling operations that require both agents. 

Tasks with mandatory joint object handling. FurnMove and the large-object transport scenarios in Moving Out require sustained joint handling (Jain et al., 2020; Kang et al., 2026). Cooperation re-quirements depend on observed object properties or capability limits, as in macro-action warehouse tasks and GroundAct (Amato et al., 2019; Wang et al., 2025b). TIHDP and proactive collaboration methods also use interaction or execution feedback to assess feasibility and assistance needs (Naito et al., 2025; Li et al., 2026). Building on these precedents, HiddenCoop specifies an explicit infor-mation protocol: an unconfirmed category’s requirement remains hidden to ordinary observation and is revealed through valid grasp interactions. Evidence is initially available to participating agents, and confirmed requirements are reusable across same-category instances within the episode. 2.2 EMBODIED MULTI -A GENT PLANNING 

Planning for individually executable subgoals. CoELA, REVECA, and CaPo use communica-tion and task information to coordinate execution and revise plans (Zhang et al., 2024; Seo et al., 2025; Liu et al., 2025). CoTS searches collaborative plans, whereas COMBO uses a compositional world model to simulate joint-action outcomes (Zu et al., 2025; Zhang et al., 2025). PCE evaluates uncertain scenarios through likelihood, goal-directed gain, and execution cost, while CoBel-World maintains structured beliefs (Seo et al., 2026; Wang et al., 2025a). KGLAMP connects knowl-edge graphs to symbolic planning and evaluates repairs by likelihood and plan cost (Shek et al., 2026). DPGP focuses on task-constrained resource-discovery distributions, comparing exploration and transport candidates on shared sampled outcomes under explicit joint execution constraints. 

Planning for mandatory joint object handling. Macro-action decentralized policies coordinate joint execution through temporally extended actions, while CT-TCBS jointly plans team formation and transport using specified task locations and team-size requirements (Amato et al., 2019; Zhou et al., 2026). Learned policies and interaction feedback also support adaptive assistance (Naito et al., 2025; Li et al., 2026). RoCo combines language-based coordination with motion planning and feedback (Mandi et al., 2024), while LLaMAR applies feedback-driven joint planning to tasks including rescue with predefined two-agent carrying requirements (Nayak et al., 2024). DPGP fo-cuses on the choice between further exploration and currently executable work, accounting for ob-ject assignments and both agents’ ongoing actions. Plans are revised using local observations and communicated evidence, incorporating newly confirmed cooperation requirements. 

## 3 BENCHMARK 

HiddenCoop extends C-WAH and TDW-MAT (Zhang et al., 2024) with hidden cooperation require-ments. The resulting tasks combine individually executable subgoals with mandatory joint object handling under partial observability and decentralized control. 3.1 PROBLEM FORMULATION 

Two agents, indexed by i ∈ { 0, 1}, work toward a public goal specification G, which identifies target categories, required counts, and destination conditions. At decision step t, each agent acts using only its history of local observations and actions, execution feedback, and messages delivered to it. The action and communication rules are public, but complete object locations and unconfirmed cooperation requirements are not provided. Requirement discovery and joint execution. Solo or paired grasp attempts reveal requirements to participating agents only after passing public preconditions independent of the hidden attribute, including reachability and occupancy checks. A solo attempt on a cooperative object is then blocked, whereas a paired attempt on an ordinary object proceeds as an individual grasp. Failed precondition checks do not reveal requirements: discovery requires valid interaction, not necessarily a failed solo grasp. Cooperative objects require paired grasping and release, spatial coupling during transport, and continuous occupancy of both agents, preventing independent handling of other objects. These task-level pairing, occupancy, and distance constraints do not explicitly model shared-load dynamics. Successful execution is verified from the resulting simulator state rather than action submission. 

Environment instantiation and matched tasks. C-WAH provides room-level symbolic obser-vations, with closed-container contents hidden until opened. Goals specify category counts and 

ON /INSIDE relations and accept eligible same-category instances; these counts do not specify the total eligible supply available in the scene. TDW-MAT provides local visual observations with ground-truth instance masks for object identification. We use a container-free transport setting that excludes initially contained targets. Active-target category counts are public, but locations must be acquired through local observation or communication. Every active target must be transported and released in the goal region; same-category instances are not interchangeable. Each source task yields matched ordinary and cooperative episodes with identical initial scenes, agent positions, and semantic goals. Ordinary episodes permit individual handling of all task-relevant objects, while cooperative variants require both agents for selected categories. Both variants share the same observation and action interfaces, the communication protocol, and the execution-time model; episode-variant labels remain hidden. C-WAH contains 50 matched pairs (100 episodes) and TDW-MAT 24 (48 episodes), supporting controlled comparisons of the effects of hidden coop-eration requirements. Full execution protocols are provided in Appendix A. 

## 4 METHOD 

Discovery-Probability Graph Planning (DPGP) coordinates exploration and transport using con-firmed knowledge and probabilistic resource-discovery beliefs. As shown in Figure 2, each agent follows a time-step loop: receiving local observations, execution feedback, and delivered messages, updating persistent memory, then planning and executing. New observations and feedback close the loop. We first outline the framework, then detail discovery-probability planning. 4.1 FRAMEWORK OVERVIEW 

Our framework consists of three modules: (1) an Observation Module that maintains information across time steps; (2) a Planning Module that coordinates joint exploration and transport; and (3) an Execution Module that translates assigned plans into environment actions. 

Observation Module. Each agent i accumulates information from local observations, execution feedback, and delivered messages. Its confirmed knowledge is represented by a fact graph Fit ,recording public goals, observed entities and spatial relations, confirmed cooperation requirements, exploration evidence, and known agent states. A separate discovery belief Bit represents uncertainty about the counts and locations of undiscovered task-relevant resources. The fact graph preserves available evidence, while the belief supports reasoning about potential discoveries. LLM hypotheses and sampled objects are never recorded as confirmed facts.

Execution Module. The module translates each agent’s assigned actions into executable naviga-tion and object-handling actions, maintaining ongoing actions across time steps. Valid interactions can confirm cooperation requirements, updating memory and triggering replanning. 4.2 DISCOVERY -P ROBABILITY GRAPH PLANNING 

At each coordination round, DPGP constructs a joint plan through three stages: (1) Memory Fusion integrates available evidence from observations and messages; (2) Graph Update incorporates con-firmed structure and updates discovery beliefs; and (3) Plan Evaluation compares exploration and transport candidates through shared sampling and deterministic joint search. 

Memory Fusion. The planning agent combines local facts with information received from its partner. Objects are aligned by identity, and repeated observations are consolidated to avoid counting evidence twice. Dynamic states are updated using evidence timestamps and sources. Each agent’s execution state comes from its own account: local memory for the planning agent and delivered messages for its partner. The fused fact graph records known objects, spatial relations, exploration evidence, and execution constraints without introducing assumptions about unobserved facts. For the current round, we denote the planner’s fact graph and separate discovery belief by F and B.

Graph Update. The fused facts determine known objects, spatial relations, and candidate search regions; the discovery belief models the resources that further exploration may reveal. Hypothetical discoveries remain separate from confirmed facts. ## 5 EXPERIMENT 

5.1 EXPERIMENTAL SETTINGS 

Tasks and Baselines. We evaluate on 50 C-WAH and 24 TDW-MAT matched ordinary/coopera-tive task pairs under the public HiddenCoop interfaces. Each method is evaluated with three runs per C-WAH task and one per TDW-MAT task, yielding 300 and 48 episode records, respectively, with matched task and seed schedules across methods. Trajectories are collected with execution budgets of 600 s for C-WAH and 20 s for TDW-MAT, without additional step or frame limits. The main results use evaluation budgets of 200 s and 20 s, respectively. We compare DPGP with CoELA, CoTS, REVECA, and PCE (Zhang et al., 2024; Zu et al., 2025; Seo et al., 2025; 2026). All use GPT-4o-mini through environment-specific adapters, retaining method-specific prompting and sam-pling settings. Interface adaptations are described in Appendix C, and the configuration policy is summarized in Appendix C.1. 

Evaluation Metrics. We report within-budget task success rate (Task SR), embodied execution time (EET), and time-normalized goal-completion area under the curve (TGC-AUC); formal defini-tions are given in Appendices A.4, A.5, and D.2. EET includes physical execution, communication, and idle costs but excludes LLM inference and planning wall-clock time. TGC-AUC integrates the completed-goal fraction over the evaluation budget and normalizes by that budget, rewarding earlier goal completion. Results include successful and valid failed episodes, grouped into all, ordinary, and cooperative tasks. Goal completion rate (Goal CR) pools completed over required goal instances; token usage sums both agents’ recorded LLM usage per episode. 

Additional Analyses. We reevaluate recorded execution trajectories at 100–600 seconds in 50-second increments for C-WAH and 10–20 seconds in one-second increments for TDW-MAT. These are cutoff analyses, not budget-conditioned reruns; completion after each cutoff receives no success or AUC credit. Table 1 shows that DPGP delivers the best overall and cooperative-task performance in both environ-ments, achieving the highest Task SR, lowest EET, and highest TGC-AUC. ## 6 CONCLUSION 

We introduced HiddenCoop to study multi-agent exploration and execution with interaction-revealed cooperation requirements. Our framework, DPGP, combines confirmed facts with resource-discovery beliefs to evaluate exploration and transport jointly under execution constraints. Experi-ments on C-WAH and TDW-MAT show strong cooperative-task performance, improved execution efficiency and goal progress, and substantially lower LLM token usage. Common-success and ex-ecution trajectory analyses further distinguish execution efficiency from final task success. These findings support evaluating potential discoveries together with their downstream execution costs when coordinating partially observable tasks. Task groups (all, ordinary, and cooperative), outcome groups (all, success, and failure), and target types (ordinary and cooperative) are separate grouping dimensions. A cooperative task may contain ordinary targets. An empty group is reported as unavailable rather than assigned a zero rate. Input, output, and total LLM tokens and call counts are summed across both agents’ recorded at-tempts, then averaged over episodes. The EET decomposition separates physical time, the idle-only charge, and additional communication time on the joint critical path. LLM and planner wall-clock time are separate diagnostics. In C-WAH, unavailable token fields are excluded from the correspond-18 ing field-wise mean. In TDW-MAT, available token usage is summed within each episode, missing call-level fields contribute zero, and the mean uses all valid episodes in the group. Missing-usage calls are recorded separately. Shorter-budget results replay complete steps from trajectories collected at the main budget: 100– 600 s in 50 s increments for C-WAH and 10–20 s in 1 s increments for TDW-MAT. The first step crossing a shorter budget is retained with its full cost, so terminal EET may exceed B; progress first achieved after B does not contribute to budget-limited success or TGC-AUC. These results describe actions of the recorded trajectories, not online reruns in which a method was informed of a different budget. D.3 PAIRED AND CONDITIONED COMPARISONS 

Ordinary and cooperative variants are matched within each source pair. We report the ordinary-to-cooperative change using paired outcomes, with uncertainty intervals from 5,000 bootstrap re-samples of source pairs. C-WAH resamples 50 pairs while keeping each pair’s three runs together; TDW-MAT resamples 24 pairs from its single run. These intervals describe variation across the evaluated source pairs and do not quantify independent model or simulator-run variability. For common-success efficiency, every compared method is evaluated on the same successful episode identifiers. The five main methods share 264 successful C-WAH episode-run records (150 ordi-nary and 114 cooperative) and 12 successful TDW-MAT episodes (10 ordinary and 2 cooperative). Efficiency comparisons on the two cooperative TDW-MAT episodes are descriptive. Timeout is recorded as a termination condition, not assigned as the sole cause of a failed task.

## F TRACE -L EVEL CASE STUDY 

We use C-WAH task16 to illustrate how belief revision changes executable exploration. The ordinary task requires one apple, one wine, and one pudding on coffee table 268. The probability and single-point versions start from the same scene, but their internal decisions and subsequent observations need not remain identical; the case is illustrative rather than a controlled module ablation. At the first probability decision, support levels 0 and 1 for zero versus one anonymous object nor-malize to probabilities 1/3 and 2/3. Six candidates receive mean scores 122.85, 123.16, 122.30, 122.13, 125.98, and 121.90. Candidate 0 is selected even though candidate 5 has the smallest dis-played mean, consistent with the recorded one-standard-error eligibility and analytic tie break. When a new container appears at step 6, the probability version assigns one agent to continued exploration and the other to dishwasher 104; the single-point version instead schedules an unknown-region alternative in bathroom 172. The probability trace opens the dishwasher at step 13 and records wine 368 and apple 373 by step 15, then opens the microwave at step 20 and grasps pudding 370 at step 23. The single-point trace reaches the relevant refrigerator/microwave stage around step 51. These are control-step indices, not uniform time units. The probability trace delivers pudding, wine, and apple at steps 46, 51, and 84, completing in 94.4532 s with AUC 0.6579. The single-point trace delivers wine, pudding, and apple at steps 73, 76, and 111, completing in 125.6664 s with AUC 0.5067. Their recorded model usage is 2 calls/5,672 22 tokens versus 12 calls/17,174 tokens; neither trace records an execution-failure event. The 31.2132 s difference is consistent with the earlier discovery schedule, but cannot be attributed solely to un-certainty representation because the system versions are not otherwise identical. As an ordinary episode, task16 demonstrates search and transport scheduling rather than the paired-manipulation transaction. 

## G LLM P ROMPTS 

The only use of large language models (LLMs) in our method is the semantic discovery-support estimation described in Appendix B.1; all other components are deterministic. At each request, the method assembles the required rows (anonymous count hypotheses or semantic location groups) from public task information, and the LLM returns an integer support level Lj ∈ { 0, . . . , 4} for every candidate, which is converted into relative weights by Equation equation 10. The prompt structure is shared across agents and requests; the rows supplied as input differ. The complete C-WAH and TDW-MAT prompts are listed below. 

Discovery-support estimation prompt (C-WAH) 

Estimate a finite discovery model from public household semantics. OUTPUT FORMAT: Return only a json object with exactly one field, "rows", containing an array. Each row has EXACTLY "key" and "levels". Copy its key and every candidate_id from required_rows exactly once. Every value in "levels" must be one of the JSON numbers 0, 1, 2, 3or 4. Never return probabilities, counts, arrays, input metadata or explanations in a row. Fictional format example (NOT this request): {"rows":[{"key":"count :fictional_item","levels":{"n0":1,"n1":3,"n2":2,"n3":0}}, {"key":" place:fictional_item","levels":{"g0":1,"g1":4}}]}. Code maps each level L to 2**L and normalizes the row. Equal levels are valid when evidence does not distinguish alternatives. Do not force differences or assign high support simply because a task needs an object. Judge whether a useful object is physically stored there now and would be found by inspection. This is storage/discovery likelihood, not a broad association between the object and activities performed near that location. Estimate anonymous supply separately from task demand; do not assume every inspected container yields a useful object. Do not predict cooperative labels, navigation costs or actions.
