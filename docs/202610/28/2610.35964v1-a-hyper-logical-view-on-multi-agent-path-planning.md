## 摘要
多智能体路径规划（MAPP）要求为多个智能体规划无碰撞路径。MAPP在现实中有大量应用，包括自动驾驶车辆的导航，因此存在许多考虑不同约束、需求和目标的变体。对于每一种此类变体，通常都会开发新的算法处理方式。本文采取一种互补的、以规约为中心的观点：我们表明，许多MAPP变体可以在HyperLTL——一种能够推理多条路径及其随时间演化的时序逻辑——及其ω正则扩展HyperQPTL中建模。本文的贡献并非主张当前的超性质模型检测器可以替代专用的MAPP求解器。相反，超逻辑视角提供了一种统一语言，用于比较MAPP变体、添加跨智能体约束、表达最优性，并将MAPP与面向超性质的验证、解释和因果性技术联系起来。

## Abstract
Multi-Agent Path Planning (MAPP) requires collision-free paths for multiple agents. MAPP has numerous real-life applications, including the navigation of automated vehicles, and has therefore many variants considering different constraints, requirements, and objectives. For each such variant, a new algorithmic treatment is often developed. This paper takes a complementary, specification-centered view: we show that many MAPP variants can be modeled in HyperLTL, a temporal logic that reasons about multiple paths and their evolution through time, and in its omega-regular extension HyperQPTL. The contribution is not a claim that current hyperproperty model checkers replace specialized MAPP solvers. Rather, the hyper-logical view gives a unified language for comparing MAPP variants, adding cross-agent constraints, expressing optimality, and connecting MAPP to verification, explanation, and causality techniques for hyperproperties.

## 2. 方法论

### 2.1 核心思想

- 用 **HyperLTL** 描述"多条路径之间关系"的性质：一条 trace 对应一个智能体的路径，路径量化（∃π / ∀π）天然对应"存在一组无碰撞路径"的规划语义。
- 采用**模块化分解**：把问题拆成
  - `φ_start`：各智能体从指定起点出发；
  - `φ_goal`（或变体专属的目标公式）：目标满足；
  - `φ_no-conf`：无碰撞（顶点冲突 / 边冲突可替换）；
  - 成本/最优性作为**独立可插拔组件**。
- 变体之间的差异往往只需替换其中一个局部合取项，而非重新设计算法。

### 2.2 关键技术细节

- **实例到 LTS 的转换**：给定无向图 G=(V,E)、智能体集合 A、起点 S，构造标签迁移系统 `T_G = (V, V, δ_E, L)`，其中 `δ_E` 含等待动作（v=v′）与双向边，`L(v)={v}`；证明 `TRACES(T_G)` 恰为实例中所有可能路径（Observation 1）。
- **HyperLTL 语法/语义**：在 LTL 上增加 trace 变量与量词 `∃π.φ / ∀π.φ`；`p_π` 表示命题 p 在 trace π 上成立；`○`（next）、`U`（until），派生 `◇`（eventually）、`□`（globally）。
- **HyperQPTL**：额外允许对原子命题量化 `∃q.φ`，用于表达 ω-正则超性质；本文用其"量化命题"作为**全局辅助标签**（例如标记智能体满足目标的唯一时刻）。作者指出 HyperQPTL 不增加计算复杂度，但 HyperLTL 更常用，故优先使用 HyperLTL。
- **九个变体的编码要点**：
  1. **MAPF**：`φ_start ∧ φ_goal ∧ φ_no-conf`；`φ_goal` 用 `□g_i` 表示"到达后永久停留"，同时允许此前途经目标点。
  2. **AMAPF**：引入存在量化的 `π′` 满足目标，并用 `∀τ.∃τ′` 的 trace 等式约束诱导起点到目标的**双射分配**；因此省略 `φ_no-conf(π′)`（作者称其为冗余）。
  3. **MCPF**：`φ_goal-MCPF = ⋀_j ⋁_i ◇g_j^{π_i}`，即每个目标被某个智能体到达（可多目标/零目标）。
  4. **TAPF**：`⋀_i ⋁_{g∈gset_i} ◇g^{π_i}`；并说明 AMAPF 也可用 `gset_i = G` 的 TAPF 模式编码，保留独立编码是为显式表达"匿名分配"。
  5. **MAPD**：`⋀_j ⋁_i ◇(p_j^{π_i} ∧ ◇d_j^{π_i})`，保证先取后送。
  6. **MAPF-PC**：需 HyperQPTL；为每个智能体引入量化命题 `q_i`，用 `ψ_i` 约束 `q_i` 恰好出现 `m_i` 次，`φ_gseq(π_i)` 约束目标序列顺序，`φ_(g_i^x,g_j^y)` 比较不同智能体被标记的满足时刻以表达**跨智能体优先约束**。
  7. **RMAPF**：只改冲突公式为"未来 k 步内不得占用同一顶点"。
  8. **MTPF**：冲突公式同时约束 head 与 k 段 tail；关键技巧是用 `U` 追踪**位置序列的变化**（而非时间步），表达"任意 k+1 个连续占用位置"不得与其它智能体冲突。
  9. **MAM**：`⋁_v (⋀_i ◇v^{π_i} ∧ 其它顶点两两不冲突)`，即选共同会合点，会合点本身允许重合。
- **目标假设可切换**：把 `□g` 改为 `◇g` 即可表达"到达后清空目标点、可继续移动"的语义，体现模块性。
- **成本函数（makespan）**：
  - 直接法：`φ_MAPF-makespan = φ_MAPF ∧ ∀π′.(φ_MAPF(π′) → ⋁_i ⋀_j (¬g_i^{π′_i}) U (g_j^{π_j}))`，即"任何其它解中总有智能体不早于当前解全部到达"。
  - 标签法（HyperQPTL）：为每个智能体引入"恰好出现一次"的标签 `l_i`（`φ_once_i`），使 `l_i` 的成立时刻等于该路径长度，从而把 makespan 比较变成**与问题无关的统一后缀** `φ_L-makespan`；附录对九个变体逐一给出 `φ_L` 版本（MCPF/MAPD 用"最后一个被满足的目标"作标签，MAPF-PC 用最后一个 `q_i` 标记）。
- **最优解存在性归约**：`ψ_opt := ∃π_1…∃π_n. φ_MAPF-makespan`；**Theorem 2**：`T_G ⊨ ψ_opt` 当且仅当存在最优解，且最外层存在量词的见证即为最优解。
- **量词交替分析**：模型检测复杂度随路径量词交替次数指数增长；本文公式基本为 `∃*∀*` 形式，作者刻意最小化交替次数。

## 6. 主要结论与发现

- 九种主流 MAPP 变体可**模块化**地编码进 HyperLTL（MAPF-PC 需 HyperQPTL），共享 `φ_start / φ_goal / φ_no-conf` 骨架，差异集中在局部合取项。
- HyperLTL 天然表达**跨智能体路径关系**，可加入 CBS 等解耦式算法难以表达的约束（如"a₁ 始终位于 a₂ 的邻域内"的公式 (1)），并可与任意变体公式合取。
- **makespan 最优性可作为超性质表达**，并归约为 HyperQPTL 模型检测的存在性判定；用"量化命题标签"可把成本比较与具体问题解耦，形成通用后缀。
- **SOC（sum-of-costs）无法在同步 HyperLTL/HyperQPTL 中表达**，因为需要对不同 trace 的位置做异步推理，需借助异步时序超逻辑（如 Bombardelli 等 2025）。
- 复杂度主要来自**路径量词交替**；本文公式为 `∃*∀*`，与更简单问题所需的交替层级相当。
- 该视角的价值是**概念性与方法论的**：为 MAPP 提供统一规格语言，为超性质社区提供带丰富跨 trace 结构的真实规划问题族，并为**形式化解释与因果分析**提供接口（"哪些 trace 关系导致了冲突被避免 / 目标被延迟"）。

- **教学与社区沟通价值**：九个变体的并列编码本身就是一份高质量的"变体语义对照表"，可用于向新入门者说明 MAPF/AMAPF/TAPF/MAPD 等名词之间的精确差别，其价值独立于是否真的用模型检测器求解。

- **贡献性质**：这是一篇**立场/视角论文（position & modeling paper）**，核心贡献是统一的形式化语言与模块化编码方案，而非算法或系统。其价值应按"是否提供了更好的问题描述与比较工具"来评判，而非按求解性能评判。
- **成立的部分**：模块化骨架（`φ_start / φ_goal / φ_no-conf` + 可插拔成本）确实统一了九种变体，且跨智能体约束（公式 (1)）与 makespan 标签化技巧是实质性的表达力展示；Theorem 1、Theorem 2 为 MAPF 与最优性归约提供了可靠支点。
- **未成立或待补的部分**：除 MAPF 外的正确性论证偏概要；SOC 缺席削弱了"统一语言"的完整性；零实证使可行性边界未知；附录与正文在 AMAPF 冲突项上的不一致属于可修正但应指出的瑕疵。
- **适用读者**：适合 MAPP 研究者（用于厘清变体语义、寻找新约束的表达方式）、形式化方法/超性质验证研究者（用于获取带丰富跨 trace 结构的应用问题族），以及需要向他人精确解释 MAPP 变体差异的工程实践者；不适合期待即用型求解器或性能基准的读者。
- **一句话结论**：本文把"多智能体路径规划变体的差异"从算法实现细节提升为可书写的规格差异，给出了一个自洽、模块化、表达力有针对性但**尚未经验检验**的形式化框架；它更像一张精确的地图而非一条已修好的路。
