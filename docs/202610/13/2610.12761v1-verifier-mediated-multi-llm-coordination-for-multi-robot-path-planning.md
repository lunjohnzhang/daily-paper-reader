## 摘要
基础模型正越来越多地用于高层多机器人任务规划，然而，由于共享的空间和时间约束，独立生成的符号计划在几何落地后可能变得联合不可行。我们研究面向多机器人导航的大语言模型（LLM）规划器的执行感知协同。我们将一种集中式架构（其中一个LLM对机器人团队进行联合推理）与一种分散式多LLM架构（其中每个机器人独立提出任务计划）进行比较。几何验证器将候选计划落地为机器人轨迹，检测预测的机器人间冲突，并将冲突信息转换为结构化反馈以进行有针对性的重规划。这种验证器介导的架构将语义任务推理与执行级可行性分离，同时支持LLM规划器之间的迭代协同。在CARLA和Crazyflie空中机器人上的实验评估了随着任务复杂度增加的协同性能，并刻画了集中式推理、分散式验证器介导协同与物理可执行性之间的权衡。

## Abstract
Foundation models are increasingly used for high-level multi-robot task planning, yet independently generated symbolic plans can become jointly infeasible after geometric grounding because of shared spatial and temporal constraints. We study execution-aware coordination of large-language-model (LLM) planners for multi-robot navigation. We compare a centralized architecture, in which one LLM jointly reasons over the robot team, with a decentralized multi-LLM architecture in which each robot independently proposes a task plan. A geometric verifier grounds the candidate plans into robot trajectories, detects predicted inter-robot conflicts, and converts conflict information into structured feedback for targeted replanning. This verifier-mediated architecture separates semantic task reasoning from execution-level feasibility while enabling iterative coordination among LLM planners. Experiments in CARLA and on Crazyflie aerial robots evaluate coordination performance as task complexity increases and characterize the trade-offs between centralized reasoning, decentralized verifier-mediated coordination, and physical executability.

## 2. 方法论

- **核心思想**：每个机器人级 LLM 提出符号任务计划，几何规划层将其落地为可执行轨迹；共享执行级验证器检查轨迹间的障碍与机器人间冲突；若预测冲突，则将冲突转化为结构化反馈，返回给受影响 LLM 进行定向重规划，迭代至所有候选轨迹满足执行级约束。
- **任务与路径表示**：
  - 环境表示为图 \(G=(V,E)\)，节点为可允许符号状态，边为有效转移。
  - 机器人 \(i\) 的任务为 \(\tau_i := \{s_i, g_i, W_i, F_i, C_i\}\)，包含起点、目标、需访问目标集及任务约束。
  - LLM 生成符号计划：\(p_i = P_{\text{LLM},i}(\tau_i, G, I_i)\)，其中 \(I_i\) 为规划器上下文，可包含先前执行级反馈。
- **几何落地**：
  - 通过映射 \(\Gamma: V \rightarrow X\) 将符号状态映射到机器人状态空间中的几何锚点。
  - 再用局部几何规划器 \(\Pi_{\text{loc}}\)（如 A*）连接锚点，得到轨迹：\(\xi_i = \Pi_{\text{loc}}(\Gamma(p_i))\)。
- **集中式与去中心化架构**：
  - 集中式：单 LLM 接收联合团队任务，同时生成所有机器人计划 \(\{p_1,\dots,p_M\} = P^c_{\text{LLM}}(\tau_1,\dots,\tau_M,G,I)\)。
  - 去中心化：每台机器人有独立 LLM 规划器，不直接进行无限制自然语言协商，而是通过共享执行级验证器耦合。
- **执行级冲突验证与反馈**：
  - 对每对机器人 \((i,j)\)，验证器要求 \(\|\xi_i(t)-\xi_j(t)\| \ge d_{\min}\)，对所有 \(i \ne j\) 和 \(t \in [0,T]\) 成立，\(d_{\min}>0\) 为规定分离阈值。
  - 若违反，验证器识别预测冲突，构造结构化反馈对象：\(\psi_i^{(r)} = \Psi(j, t_c, x_c, d^{ij}_{\min})\)，其中 \(t_c\)、\(x_c\) 为预测冲突时间与位置，\(d^{ij}_{\min}\) 为最小预测分离。
  - 受影响机器人重规划：\(p_i^{(r+1)} = P_{\text{LLM},i}(\tau_i,G,I_i \cup \psi_i^{(r)})\)。
  - 重规划仅针对受影响智能体，其他智能体的可行计划可保留；当所有候选轨迹满足执行级约束时终止。

## 6. 主要结论与发现

- **集中式与去中心化的权衡**：
  - 目标集较小时，集中式规划计算开销更低，因为单 LLM 可联合推理完整多智能体状态并在生成阶段考虑交互。
  - 随任务复杂度增加，两者性能差距缩小，去中心化的协调开销部分被其模块化规划结构抵消。
- **环境表示影响规划可靠性**：
  - 邻居列表输入持续产生图有效的可行路线，路径长度与集中式规划相当。
  - 原始坐标输入提供更大几何灵活性，偶尔产生更短轨迹，但更容易生成无效或出图路点。
- **冲突难度随复杂度增加**：
  - 目标点越多，轨迹越长、路点排序空间越大、机器人间冲突越频繁，迭代重规划解决冲突更难，凸显显式执行级可行性检查的重要性。
- **跨平台可迁移性**：
  - Crazyflie 仿真表明验证器介导架构可支持两架独立任务四旋翼通过轨迹级冲突检查与重规划协调。
  - 物理实验表明相同符号—几何规划与可行性流水线可部署到真实空中硬件，尽管存在跟踪误差、执行器动力学、定位不确定性和外部扰动。
- **总体结论**：验证器介导架构可分离高层语义推理与执行级可行性，为去中心化基础模型推理与执行感知多机器人协调提供具体接口。
