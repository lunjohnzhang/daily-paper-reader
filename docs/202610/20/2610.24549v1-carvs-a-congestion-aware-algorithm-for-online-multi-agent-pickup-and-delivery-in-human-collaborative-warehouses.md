## 摘要
智能仓库系统通过集成机器人且仅需极少基础设施改造，改变了物流行业，与仅由人工操作的传统模式相比，提高了效率并优化了工作流程。然而，人机协作带来了新的挑战，特别是人的不确定性会导致动态交互和不可预测行为。为应对这些复杂性，本文提出人机协作多智能体取送货（MAPDwHC）问题，它是多智能体取送货（MAPD）问题的扩展，纳入了人的不可预测性。该问题增加了关键约束，例如机器人与人类交互时临时阻塞路径所造成的动态障碍，以及对实时响应能力的需求。我们对MAPDwHC问题进行了形式化，并给出了附加约束与性质。基于该问题设定，我们提出CARVS算法，通过集成任务交换、验证检查和随机初始化来改进任务分配与路径规划。CARVS减少拥塞，增强对人机交互的适应性，并确保实时响应能力。仿真结果表明，在传统MAPD算法失败的大规模场景中，CARVS显著减少了路径规划超时，同时提升了效率与可扩展性。

## Abstract
Intelligent warehouse systems have transformed logistics by integrating robots with minimal infrastructure changes, boosting efficiency and optimizing workflows compared to traditional human-only operations. However, human-robot collaboration introduces new challenges, particularly due to human uncertainty, which leads to dynamic interactions and unpredictable behavior. To address these complexities, this paper presents the Multi-Agent Pickup-and-Delivery with Human Collaboration (MAPDwHC) problem, an extension of the Multi-Agent Pickup-and-Delivery (MAPD) problem that incorporates human unpredictability. This problem adds key constraints, such as dynamic obstacles caused by robots temporarily blocking paths when interacting with humans, and the need for real-time responsiveness. We formalize the MAPDwHC problem with additional constraints and properties. Based on this problem setting, we propose the CARVS algorithm, which improves task assignment and path planning by integrating task swapping, validation checks, and random initialization. CARVS reduces congestion, enhances adaptability to human-robot interactions, and ensures real-time responsiveness. Simulation results show that CARVS significantly reduces timeouts of path planning in large-scale scenarios where traditional MAPD algorithms fail, improving both efficiency and scalability.

## 1. 核心问题与研究动机

- **背景**：现代电商仓储中，机器人（AMR）负责运输，人类工人负责拣选与打包（因商品尺寸、包装差异大，机械抓取不可靠）。全自动化改造成本过高，因此人机协作是现实主流形态。
- **问题缺口**：经典 MAPD（Multi-Agent Pickup and Delivery）假设环境中没有人类，无法刻画真实仓库中的人类不确定性：
  - 机器人与人交互时必须**原地静止**，临时成为**动态障碍**，在狭窄通道中可能直接切断图连通性，使部分 MAPF 实例无解；
  - 人类不遵循固定时间表，交互的**开始时刻与持续时长**均随机，结束时间不可预知；
  - 系统要求每个时间步在 **η 秒内**给出可行解，否则所有机器人停摆（"skip"），即**实时响应性**约束。
- **整体含义**：论文将上述要素形式化为 **MAPDwHC（Multi-Agent Pickup-and-Delivery with Human Collaboration）** 问题，指出它是 MAPD 的严格扩展（MAPD 是交互恒为空的特例），并在实验上证明：直接套用传统 MAPD 算法时，任务完成量可跌至其自身峰值的 10% 以下。

## 2. 方法论

### 2.1 问题形式化

- 环境为无向图 $G=(V,E)$，离散时间步，每步对应 η 秒真实时间；任务 $\tau_j=(s_j, r_j)$，$r_j$ 为释放时间，取货点 $s_j \in V_P$、送货点 $V_D$（多个公共打包站，通常选最近者）。
- 每个 agent 最多同时携带 $K$ 个包裹；$\sigma(a_i,t)\in\{0,1\}$ 表示 agent 是否正在与人交互，交互期间 agent 位置冻结（Property 1，动态障碍）。
- 目标：在时间窗 $T$ 内最大化完成任务数 $|e_T|$。
- **良构实例（well-formed）**：需满足地图连通（Property 3）、交互时长有限（Property 4）、度数 ≥3 的交叉点数量不少于 agent 数（Property 5）。Theorem 1 证明：在"目标不重叠"分配假设下，良构实例可被任意完备 MAPF 算法求解；Theorem 2 证明良构 MAPDwHC 可随时间退化为一系列 MAPD 实例，从而支持与传统 MAPD 算法对比。

### 2.2 核心思想：分层解耦 + 三项轻量改进

将问题分为**高层任务分配**与**低层路径规划**两层，刻意不做联合优化（作者认为联合搜索空间在 1 秒预算内不可行，TP/TPTS、MCA/RMCA 正是因此在复杂地图上崩溃）。底层采用**完备 MAPF 求解器**（实验选用 LaCAM2），以继承完备性保证。

基线为**贪心分配（GA）**：空闲 agent 选最近取货点，满载 agent 选最近送货点；FCFS 是 GA 的特例。CARVS 在 GA 上叠加三项改进：

- **随机初始化（Random Initialization）**：当 agent 空载（$c_i=0$）时，从当前可分配任务集 $T_t$ 中**随机**选取第一个目标；后续任务仍取最近者。目的是打散机器人分布，缓解因任务空间分布不均（尤其卸货区附近）造成的拥塞与瓶颈。
- **验证检查（Validate Assignment）**：用 A\* 类路径规划器 $\omega$ 预判目标可达性；若不可达，则改派到**等待点** $w_i \in V_W$，其中 $V_W$ 定义为既非取/送货点、且删除后图仍连通的非割点集合。等待点按曼哈顿距离就近选择，并要求各 agent 目标互不重叠。
- **任务交换（Task Swapping）**：仅允许在**取货前**（任务状态均为"已分配=1"）交换目标。当两 agent 的最短路径互相经过对方当前位置、且交换后新路径不再互穿时，交换二者目标。由于实物包裹不可交换，已取货/送货阶段的任务不允许交换。

### 2.3 算法流程（Algorithm 1 概要）

1. 遍历 agent：已有目标则跳过；未满载且空载 → 随机初始化目标；未满载且非空载 → 最近取货点；满载 → 最近送货点。
2. 复制图 $G'$，将与人类交互中的 agent 所在顶点从 $G'$ 删除（落实动态障碍语义）。
3. 两两检查满足交换条件的 agent 对，执行目标交换。
4. 对每个 agent：若存在目标且 $\omega(G', v, g)\neq\varnothing$，加入起点–目标对集合 $M$；否则改派最近等待点后加入 $M$。
5. 调用完备 MAPF 求解器 $\Omega(G', M)$ 输出联合路径 $P$。

Theorem 4 证明 CARVS 配合任意完备 MAPF 算法可解任意良构 MAPDwHC 实例。

## 3. 实验设计

- **地图/场景**：4 种布局——`warehouse_tiny`（源自 TP/TPTS 研究）、`warehouse-10-20-10-2-1`、`warehouse_small`、`warehouse_large`（后两者为真实仓库布局抽象，含长隧道、高障碍密度）。论文用 5 项结构指标刻画地图难度：顶点数、障碍占比、隧道数、平均隧道长度、度数 ≥3 顶点占比。
- **任务数据**：来自真实仓储管理系统（WMS）的 SKU 任务事件流，原始任务量偏少，故将每个任务重复 10 次以构造更大任务集，并按原始时间分布持续投放，形成非均匀空间分布。
- **仿真设定**：η = 1 秒；每步机器人移动 0.75 m（一条边），人类速度 1.5 m/s（两倍于机器人）；交互时长取退化分布 $\Pr(\delta=10)=1$（10 个时间步）；人类按 A\* 路径移动，$\sigma$ 由预测轨迹生成；50 名人类工人固定不变；每配置 10 个随机种子，运行 20,000 时间步（MAPF 算法对比为 10,000 步）。
- **对比方法**：
  - **MAPF 底层求解器筛选**：EECBS、RHCR、CBSH2-RTC、LaCAM、LaCAM2、MAPF-LNS2，最终选 LaCAM2（任务完成数最高）。
  - **MAPD 基线**：TP/TPTS、MCA/RMCA、TSWAP、MAPD-d（以 k=0 的 k-TP 运行）。
  - **自研基线/消融**：FCFS、GA、CARVS-V（仅验证，无随机初始化）、CARVS-S（仅交换）、CARVS-W（仅等待点）、完整 CARVS。
- **评价指标**：完成任务总数、skip 次数（规划超时导致全体停摆的次数）。
- **附加实验**：人类效率（交互时长 δ 与人类速度的组合 D0S100、D0S2、D0S20、D10S2、D5S2）对 skip 数的影响；人类工人数量（10–100）对完成量的影响。

## 6. 主要结论与发现

- 在良构性假设下，MAPDwHC 可被完备算法求解，且可退化为时间序列上的 MAPD 实例，从而建立与既有方法的可比性。
- 传统 MAPD 算法（TP/TPTS、MCA/RMCA）在复杂地图上严重失效：agent 数超过 60 后完成量骤降，100 agent 时不足自身峰值的 10%，在更大仓库中几乎完不成任务。
- TSWAP 虽 skip 少，但因其面向无标签目标、依赖目标交换解冲突，送货机器人仅 **0.73%** 的成功路径真正到达指定卸货点（44.94% 到了别人的卸货点，54.33% 到了取货点），"规划快"不等于"任务完成多"。
- MAPD-d 因 k-TP 的 ±k 时空预留导致规划开销随 agent 数激增，100 agent 时完成量降至 2。
- CARVS 相较 GA 在最高 agent 数下将超时（skip）减少约 **90.61%**；验证检查在 `warehouse_large`、100 agent 时使完成量至少提升 **2×**，随机初始化再提升至少 **1.1×**。
- 人类效率实验显示：缩短交互时长 δ 显著降低 skip 数，而人类移动速度影响很小；MAPDwHC 的 skip 数约为对应 MAPD 设定的 **1.96×**，量化了人机协作带来的额外难度。
- 人类工人数在约 50 之后边际收益递减，为人力配置提供经验参考。

## 7. 优点

- **问题建模有价值**：把"交互时机器人静止→动态障碍""交互时长随机""1 秒硬实时预算"三条约束显式形式化，并给出良构性与可解性证明（Theorem 1/2/4），理论链条完整。
- **分层解耦的设计取舍清晰**：明确论证联合优化在实时预算下不可行，用"完备底层求解器 + 轻量高层启发式"换取实时性与可扩展性，工程可落地性强。
- **三项改进各有针对性且互相正交**：随机初始化治"空间分布不均导致的局部拥塞"，验证+等待点治"目标不可达导致求解器空转"，任务交换治"路径交叉导致的绕行"，消融实验能对应验证。
- **等待点定义严谨**：限定为非割点，保证单个 agent 驻留不破坏图连通性，体现对拓扑性质的考量。
- **实验对比扎实**：既横向比较多种 MAPF 求解器并说明选型理由，又对 MAPD 基线做了细致的在线化适配（附录 D），并给出 TSWAP 失效的量化诊断，分析深度超出一般"跑个分数"的对比。
- **真实场景支撑**：附录 A 提供真实仓库照片与部署约束说明（窄通道、无夹爪、SLAM 定位、平板人工上报状态），数据与伦理声明规范。

## 8. 不足与局限

- **规模上限偏低**：最多 100 个 agent，未验证数百至上千 agent 的可扩展性；作者以 1 秒预算解释，但这恰恰意味着方法在大规模下的表现仍属未知。
- **人类模型过于理想化**：人类按 A\* 路径移动、交互时长取确定性 δ=10、且假设人机碰撞可忽略；真实场景中人类路径随意、停留时间重尾分布，可能显著改变 skip 与完成量。
- **"全体停摆"回退策略保守**：超时即所有 agent 静止，作者承认理论上可识别"仍可安全移动"的子集，但需在指数多个 agent 子集上求解 MAPF，故未实现；这在高负载下会放大性能损失。
- **任务交换受限**：仅允许取货前交换，无法处理已装载包裹的再分配；且交换判定依赖两两路径检查，agent 数增大时组合开销可能上升（文中未报告该部分耗时）。
