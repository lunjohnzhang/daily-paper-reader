## 摘要
在灾后搜救等多机器人任务中，较短的通信距离会将无人机（UAV）集群割裂成短暂的信息孤岛。在这种间歇性连通条件下，主流的“先分配后执行”范式——要求在任一物理移动之前达成全局共识——会失效。本文提出通信约束在线性能影响（CC-OPI）算法，这是一种事件驱动方法，将任务协商与物理执行交错进行。CC-OPI 仅在离散的物理事件和拓扑事件发生时重新规划，并融合了两个进一步要素。第一个是适应动态拓扑的一对代价评估指标——一个带有空间局部性惩罚以促进区域化运行，另一个带有截止时间感知的紧迫性项——并辅以非抢占式状态锁，以保护每架无人机正在执行的动作。第二个是去中心化容错层，将基于版本的状态同步与全局时间驱动的应急池相结合。我们证明 CC-OPI 在有限时间内终止，不会出现陈旧完成死锁，也不会在任务时域内发生无界重分配。在通信半径为 250 m 的仿真中，CC-OPI 保持约 0.80 的任务完成率：它比未修改的性能影响（PI）和基于共识的捆绑算法（CBBA）规则的匹配在线执行领先约七个百分点，比朴素迁移的静态基线高出约 20 个百分点，并在全连通条件下与 PI 和 CBBA 相差仅几个百分点。在所测试的设置中，CC-OPI 随连通性减弱而优雅降级，并能吸收丢包、地形遮挡和运行时任务到达。代价是更多消息和一些冗余移动——这是为鲁棒性而有意牺牲效率的权衡。

## Abstract
In multi-robot missions such as post-disaster search and rescue, a short communication range fragments a swarm of Unmanned Aerial Vehicles (UAVs) into transient information islands. Under such intermittent connectivity, the prevailing "allocate-then-execute" paradigm--which requires global consensus before any physical movement--breaks down. This paper proposes the Communication-Constrained Online Performance Impact (CC-OPI) algorithm, an event-driven method that interleaves task negotiation with physical execution. CC-OPI replans only at discrete physical and topological events and integrates two further elements. The first is a pair of cost-evaluation metrics adapted to dynamic topologies--one with a spatial locality penalty that promotes regionalized operation, the other with a deadline-aware urgency term--complemented by a non-preemptive state lock that shields each UAV's ongoing action. The second is a decentralized fault-tolerance layer that pairs version-based state synchronization with a global-time-driven emergency pool. We establish that CC-OPI terminates in finite time, free of stale-completion deadlock and of unbounded reassignment within the mission horizon. In simulations at a 250 m communication radius, CC-OPI sustains a task completion rate of about 0.80: it leads a matched online execution of the unmodified Performance Impact (PI) and Consensus-Based Bundle Algorithm (CBBA) rules by about seven percentage points, exceeds the naively transferred static baselines by roughly 20 points, and remains within several points of PI and CBBA under full connectivity. Within the tested settings, CC-OPI degrades gracefully as connectivity weakens and absorbs packet loss, terrain occlusion, and runtime task arrival. The price is more messages and some redundant travel--a deliberate trade-off of efficiency for robustness.

- **传统范式失效**：静态"先分配后执行"（allocate-then-execute）要求任意物理移动前达成全局共识，在持续分区下无法实现；孤立子网基于过时局部视图可能把同一任务纳入多条路径，或完全忽略时间关键任务。
- **论文含义**：提出 CC-OPI，把任务协商与物理执行**交织**起来，在无联合连通性保证、网络可能整场任务持续分区的条件下实现近似全局最优的在线分配。

## 2. 方法论

### 2.1 核心思想

- 用**事件驱动的"边执行边分配"（allocate-while-executing）在线范式**替代静态分阶段规划，将算法共识与持续连通性解耦。
- 通过**空间局部性惩罚诱导的隐式协调**（无需显式消息交换）让集群在通信中断期间也能减少冲突，形成区域化运行模式。

### 2.2 事件驱动在线执行框架

- 物理执行永不因等待网络同步而暂停；核心评估引擎默认休眠，仅由三类触发事件唤醒：
  - **拓扑变化事件**：邻居进入/离开通信半径 R_c，机会性激活本地状态同步与冲突消解。
  - **任务完成事件**：完成服务或到达时物理确认已被服务，释放容量、更新完成集、评估新候选任务。
  - **心跳事件**：低频率周期性触发，扫描未完成任务的剩余时间窗，识别临近硬截止期的任务。
  - （启用运行时任务到达时还有**新任务公告事件**。）
- 每次唤醒执行**四阶段流水线**：事件处理 → 共识 → 移除 → 包含，任一阶段都不迭代到不动点，保证单次调用有界开销。

### 2.3 空间感知动态 IPI（任务包含）

- 标准 PI 用原始 IPI 衡量插入任务到路径第 n 位的目标代价增量：IPI_raw(τ_k) = min_n [F2(P_i ⊕_n τ_k) − F2(P_i)]。
- CC-OPI 引入**空间局部性惩罚因子** μ(τ_k)，将插入代价按候选任务距 UAV **初始部署锚点** p_i,init 的距离缩放：
  - μ(τ_k) = 1（无人照管的应急任务）；否则 μ(τ_k) = 1 + λ·d̄(τ_k)^γ
  - d̄(τ_k) = ‖p_τk − p_i,init‖ / D_map（按地图对角线归一化），λ > 0 控制强度，γ ≥ 1 控制增长速率。
- 动态 IPI：**IPI_dynamic(τ_k) = IPI_raw(τ_k) × μ(τ_k)**。
- **关键设计**：锚点固定于部署位置而非当前位置——漂移锚点会不断把低成本区域重定心于当前所在位置，无法抑制长距离漫游；固定锚点赋予每架 UAV 稳定空间领地，使集群自组织为区域化模式，减少重叠声明。

### 2.4 紧迫性感知动态 RPI（任务移除/保留）

- 标准 PI 用 RPI_raw(τ_k) = F2(P_i) − F2(P_i \ τ_k) 衡量移除任务的目标代价减少量；子网重连时按 RPI_raw 比较解决冲突，但忽略了**物理承诺**与**时间紧迫性**，导致分配振荡。
- CC-OPI 定义**有效 RPI** 为分段函数：
  - **RPI_eff = −∞**：若 τ_k ∈ Ω_lock（非抢占免疫集：正在服务头部任务，或正接近头部任务且剩余距离 < d_lock ≈ 50 m）——最强保留出价，锁定任务不可被共识抢占。
  - **RPI_eff = +∞**：若 t_slack = D_k − A_i,k ≤ 0，广播放弃所有权。
  - **RPI_eff = RPI_raw − ρ_urgency**：否则按紧迫性惩罚调整。
- 紧迫性惩罚：ρ_urgency = β·((t_safe − t_slack)/t_slack)^κ（当 0 < t_slack < t_safe），否则为 0；β > 0 控制幅度，κ ≥ 1 控制 t_slack → 0 时的增长陡度。在最小化目标下更低 RPI 代表更强保留出价，故减去 ρ_urgency 使越紧迫的任务越难被邻居抢占。

### 2.5 去中心化状态同步与应急救援

- **基于版本的完成同步**：
  - 每架 UAV 维护本地确认完成集 C_i 与单调递增版本号 V_i。
  - 拓扑变化事件使两机进入通信范围时，按**集合内容**合并 C_i ← C_i ∪ C_j，版本号按新记录任务数递增。
  - 版本号仅作为本地变更计数器触发重播，**不做跨机版本比较**（本地计数器互不排序，版本门控合并可能在版本相等但集合不同的两机间停滞）。
  - 每次广播携带完整完成集，属于**带版本的全状态 gossip + 单调合并**（非增量传输），完成信息按流行病协议方式通过机会性接触传播。
- **应急池与吸引力奖励**：
  - 心跳事件用**全局剩余时间** t_rem(τ_k) = D_k − t（所有 UAV 一致，故对哪些任务有风险可达成共识）扫描；若 0 < t_rem(τ_k) < T_emergency，标记并放入本地应急池。
  - 对**无人照管**的应急任务（未分配或被前拥有者以 RPI_eff = +∞ 放弃）采取两部分响应，仅对该任务暂停空间区域化：
    - **解除空间惩罚**：μ(τ_k) = 1，使 IPI_dynamic = IPI_raw，按真实价值而非被距离膨胀的代价评估——这是允许有剩余容量的 UAV 跨区域救援的主要机制。
    - **提升包含优先级**：RPI_global(τ_k) ← RPI_global(τ_k) + A_bonus，作为软优先级边际，只要足够大即可在容量竞争时偏向被标记任务。

### 2.6 理论保证

- **Lemma 1**（单次调用有界计算）：每阶段仅单遍处理，操作数有限且多项式于 N、M、C_i。
- **Lemma 2**（单调确认完成集）：C_i(t) 随 t 非减且 |C_i(t)| ≤ M。
- **Lemma 3**（最终承诺）：一旦剩余距离低于 d_lock，τ ∈ Ω_lock 且 RPI_eff = −∞，既不被共识抢占也不被移出路径头部；任务在 d_lock/v_min + s_τ 内离开路径（被服务或到达时发现已被服务而丢弃）；若锁定时仍截止期可行，则为恰好一架 UAV 的准时完成。
- **Theorem 1**（有限时间终止）：在 Assumption 1 下，T_stop ≤ T_max = max_k D_k + (max_i C_i)(D_map/v_min + max_k s_k)；终止时执行有限次操作。
- **Corollary 1/2**（无死锁、无活锁）：组件内不因陈旧完成信息重包含已完成任务；执行时域内既无陈旧完成死锁，也无无界重分配序列。
- **Remark 1**：所保证的是有限时间终止 + 无死锁/活锁，**不是**收敛到全局最优（持续分区下不可达）；从未恢复接触的组件无法消解冲突，这是无通信机会下的协调不可能性，而非算法缺陷。
- **复杂度**：每次唤醒计算 O(M C³ + N M)（C 为小常数时退化为 O(N M)，与 PI 每次迭代代价相当）；消息大小 O(M + N)；单机存储 O(M + N)；广播次数上界 E ≤ N⌈T_max/Δt⌉。

## 3. 实验设计

### 3.1 仿真场景

- **场地与集群**：10,000 × 10,000 m 灾后搜救场景；异质 UAV 集群（医疗补给 30 m/s 与食物补给 50 m/s，1:1 比例），各有固定载荷容量 C_i，通信半径 R_c = 250 m（代表商用无线电实测空对空有效距离）。
- **图论特征**：R_c = 250 m 下初始通信图通常为空，时间平均度 0.16，最大连通分量覆盖 15% 集群，每次任务约 15 次成对接触、中位时长 12 s——属严重连通性受限机制。
- **任务**：两类补给各半，服务时间 300 s（医疗）/ 350 s（食物），硬截止期均匀抽取；物理引擎步长 Δt = 1 s，心跳每 20 s 一次。
- **两种设置**：
  - **默认设置**：M = 2N，C_i = 3，截止期 [0, 2000] s（完成率接近饱和，压缩方法差异）。
  - **紧约束设置（主场景）**：M = 3N，C_i = 4，截止期 [0, 1200] s；刻意保持容量充裕（C_i·N > M），使
