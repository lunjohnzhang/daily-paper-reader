## 摘要
对同步机器人路径进行冲突扫描需要详细的碰撞检测，可能涉及每个时间步上的每一对机器人，并且在冲突修复过程中可能需要重复多次。我们提出 Multi-Robot SPITE（MR-SPITE），一种保守的、基于运动片段的过滤器，用于加速这些扫描。MR-SPITE 将每条路径划分为时间区间，并为每个片段分配保守边界。区间调度器比较时间上重叠的运动的边界：不相交的边界可证明共享窗口无冲突，而未解决的窗口则传递给底层碰撞检测器。我们将 MR-SPITE 集成到 ARC 中，并将其与基于 VAMP 的碰撞检测相结合。对于 16 个 Fetch 机器人，与采用 PRM+VAMP 的基线 ARC 实现相比，集成 MR-SPITE 的 ARC 在配对实验中实现了 7.18 倍的冲突扫描中位加速比，并使中位规划时间减少 57%。这些结果表明，运动片段边界补充了配置级碰撞加速，同时保持了底层离散扫描器的行为。

## Abstract
Conflict scanning over synchronized robot paths requires detailed collision checking, potentially across every robot pair at every timestep, and may be repeated many times as conflicts are repaired. We present Multi-Robot SPITE (MR-SPITE), a conservative, motion-segment-based filter for accelerating these scans. MR-SPITE partitions each path into temporal intervals and assigns conservative bounds to each segment. An interval scheduler compares bounds for temporally overlapping motions: disjoint bounds certify the shared window as conflict-free, while unresolved windows are passed to the underlying collision checker. We integrate MR-SPITE into ARC and combine it with VAMP-based collision checking. For 16 Fetch robots, ARC with MR-SPITE achieves a paired median conflict scan speedup of 7.18x and reduces median planning time by 57% relative to the baseline ARC implementation with PRM+VAMP. These results demonstrate that motion-segment bounds complement configuration-level collision acceleration while preserving the behavior of the underlying discretized scanner.

# MR-SPITE 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：多机器人运动规划（MRMP）在仓储自动化、工业制造等场景中需求迫切，但规模扩展面临两重计算挑战：一是单个机器人状态组合随机器人数量指数增长；二是机器人之间的相互校验随机器人数呈二次增长。
- **冲突驱动方法**（CBS、CBS-MP、ST-CBS、ARC 等）通过先独立规划、再发现并修复冲突来回避复合构型空间的显式构造，其中"最先冲突查找"（Find-First-Conflict, FFC）会被反复调用。
- **瓶颈**：对 N 个机器人、K 个同步时间步，一次完整冲突扫描最多要评估 K·C(N,2) 个"机器人对–构型"查询；每次路径修复后都可能重扫，因此即便已有 VAMP 等向量化/ SIMD 加速的配置级碰撞检测，重复扫描仍占据可观规划时间。
- **核心洞见**：与其只"加速"每一次精细碰撞检测，不如"整批消除"大量根本不需要执行的检测——用运动片段级的保守几何边界直接排除整段时间窗口。
- **整体含义**：MR-SPITE 把 SPITE 的扫掠体近似（swept-volume approximation）从"环境变化后重新验证路网运动"扩展到时序同步的多机器人路径冲突扫描，属于运动级（motion-level）过滤，可与配置级加速器（VAMP/VAMP-H）互补叠加，且不改变底层离散扫描器的判定语义。

## 2. 方法论

### 2.1 核心思想
- 对每条同步路径按**运动来源（provenance）**切分为若干半开时间区间，为每个区间预计算/在线构造保守扫掠边界；调度器只比较**时间上重叠**的区间对：边界不相交即证明该共享窗口内所有离散时间步全部无冲突（一次比较跳过整段检测）；边界相交则"不确定"，交给底层碰撞检测器。

### 2.2 关键细节
- **路径区间划分**：对机器人 $r_i$，将 $[0,K)$ 划分为互不重叠、完整覆盖的有序半开区间 $I_{i,a}=[b_{i,a}, e_{i,a})$；区间类型包括预计算 PRM 边、起点/终点连接段、目标保持段（goal hold）以及在线局部修复段。每个时间步恰属于每条路径的一个区间。
- **边界来源**：
  - PRM 边区间：离线用 SPITE 在边上密集采样构型，计算**整机与逐连杆的保守 OBB**，随路网存储复用。
  - 在线区间（起终点连接、目标等待、局部修复）：运行时构造**整机与逐连杆 AABB**，取运动过程中所有中间构型球体的最大外延。
- **共享时间窗口**：$J^{ab}_{ij} = I_{i,a} \cap I_{j,b} = [\max(b_{i,a}, b_{j,b}), \min(e_{i,a}, e_{j,b}))$，只有该窗口内的时间步才可能被同时评估。
- **区间调度算法（Algorithm 1）**：
  - 为每个无序机器人对维护独立游标，放入按 $(t, i, j)$ 排序的最小优先队列；
  - 弹出最早未解决时间步对应的机器人对，定位各自区间并求共享窗口末端 $e$；
  - 若已有候选冲突 $C^*$，把 $e$ 截断到 $\text{time}(C^*)+1$，只检查可能更早或并列的时间步；
  - **整机边界不相交** → 整个窗口判定无冲突，游标直接推进到 $e$；
  - 否则调用 `CANDIDATE LINK PAIRS` 比较**逐连杆扫掠 OBB**；若无重叠连杆对，同样整段判定安全；
  - 若仍有重叠连杆对，则在 $[t,e)$ 内调用底层扫描器 `FIND FIRST CONFLICT` 求最早冲突，并用 $(k,i,j)$ 的字典序更新 $C^*$；
  - 调度器**不提前返回**，只有当队首游标时间严格大于 $\text{time}(C^*)$ 时才终止——因此所有在该时间步及之前的机器人对要么被保守边界认证、要么被底层扫描器评估，最终返回与基线 FFC **完全相同**的规范最早冲突（严格不等号保证同时刻冲突先被处理，再按确定性机器人对次序决胜）。
- **分层过滤三尺度**：
  1. MR-SPITE：过滤完整时间窗口（整机边界）；
  2. MR-SPITE-H：过滤窗口内的扫掠连杆对，并将幸存连杆掩码（link mask）传播给底层，限制后续精细检测范围；
  3. VAMP-H：在单个构型上先比较连杆球组的包围球，再评估组内精细球对。
  - 复杂度权衡：MR-SPITE-H + VAMP-H 会引入额外的掩码构造与受限回退开销，二者可能拒绝同一批交互，因此只有"被消除的精细工作量 > 额外开销"时才有收益。
- **与 ARC 集成**：初始路径被标注为起点连接段、PRM 边、终点连接段或目标保持段；局部修复时新建修复段 AABB，同时**保留未受影响区段的来源标注并更新其时间步索引**；路径补齐等待时把追加区间显式标为目标保持段并构造 AABB。每次修改后 ARC 调用同一 FFC 接口——MR-SPITE 只改变"如何评估"，不改变"选中哪个冲突"或"如何构造修复"。
