## 摘要
多智能体系统（MAS）可以在测试时通过将复杂问题分解为并行子任务来扩展大型语言模型的推理能力。然而，现有的大多数MAS依赖于集中式编排，即由一个主智能体分配工作、收集输出并合并结果。随着子任务数量的增加，这个控制器成为通信和集成的瓶颈。我们提出了去中心化语言模型（DeLM），这是一种通过并行智能体、共享已验证上下文和任务队列来去中心化协调的MAS框架。智能体异步领取子任务、读取累积进展、执行局部推理并写回紧凑的已验证更新。共享上下文充当公共通信介质，使智能体能够基于彼此已验证的进展进行构建，而无需通过中央控制器路由每一次更新。实验上，DeLM在软件工程测试时扩展和长上下文推理方面均取得了改进。在SWE-bench Verified上，DeLM在Avg.@1、Pass@2和Pass@4上均达到最佳性能，比最强基线高出多达10.5个百分点，同时每个任务的成本降低约50%。在LongBench-v2多文档问答上，DeLM在四个前沿模型系列中实现了最高平均准确率，比最强基线提高了多达5.7个百分点。代码可在我们的项目网站https://yuzhenmao.github.io/DeLM/上获取。

## Abstract
Multi-agent systems (MAS) can scale large language model reasoning at test time by decomposing complex problems into parallel subtasks. However, most existing MAS rely on centralized orchestration, where a main agent assigns work, collects outputs, and merges results. As the number of subtasks grows, this controller becomes a communication and integration bottleneck. We propose Decentralized Language Models (DeLM), a MAS framework that decentralizes coordination through parallel agents, a shared verified context, and a task queue. Agents asynchronously claim subtasks, read accumulated progress, perform local reasoning, and write back compact verified updates. The shared context acts as a common communication substrate, enabling agents to build on one another's verified progress without routing every update through a central controller. Empirically, DeLM improves both software-engineering test-time scaling and long-context reasoning. On SWE-bench Verified, DeLM achieves the best performance across Avg.@1, Pass@2, and Pass@4, with gains of up to 10.5 percentage points over the strongest baseline, while reducing cost per task by roughly 50%. On LongBench-v2 Multi-Doc QA, DeLM achieves the highest average accuracy across four frontier model families, improving over the strongest baseline by up to 5.7 percentage points. The code is available on our project website at https://yuzhenmao.github.io/DeLM/.

# 基于共享上下文的去中心化多智能体系统 (DeLM) 论文总结

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **现有问题**：大多数多智能体系统（MAS）采用**集中式编排**（如 Claude Code Subagents、Kimi Agent Swarm、AOrchestra），由一个主智能体分配任务、收集输出并合并结果。随着子任务增多，中央控制器成为**通信和集成瓶颈**，导致：
  - 扩展性差：每次有用发现、失败或部分解决方案都必须返回主智能体，再合并广播，形成串行化瓶颈。
  - 信息失真：主智能体在路由过程中可能稀释、遗漏或扭曲重要细节。
  - 在长上下文推理中，主智能体需预先分配证据片段，但往往不知道哪些相关，导致反复迭代和延迟。
- **研究动机**：需要一种**去中心化的协调机制**，让智能体通过共享状态异步协调，避免中央瓶颈，同时保证共享信息的可靠性和可扩展性。
- **整体含义**：提出 **DeLM (Decentralized Language Models)** 框架，将协调从中央控制器转移到共享问题状态，使并行智能体能够高效共享进展、避免重复劳动，提升测试时扩展能力和长上下文推理能力。

## 2. 论文提出的方法论

### 核心思想
- 去中心化协调：智能体通过**共享上下文（Shared Context）** 和**任务队列（Task Queue）** 异步协作，没有中央控制器。
- 共享上下文作为公共通信介质，每个智能体写入的更新需经过**验证（Verified）** 后才会被其他智能体可见。
- 智能体以**紧凑摘要（Gist）** 形式共享进展，并可按需“展开”到更详细的摘要或原始证据（选择性展开机制）。

### 关键技术细节
1. **两个全局结构**：
   - **共享上下文 C**：存储紧凑、已验证的进展摘要（Gist），包括源证据、完成结果、失败假设、中间约束等。
   - **任务队列 T**：存储待处理的子任务，智能体异步领取。

2. **五阶段流程**（算法1）：
   - ① 初始化任务队列（从输入分解出初始子任务）。
   - ② 并行执行子任务（智能体从T领取任务，读取C）。
   - ③ 压缩、验证并准入更新（将结果压缩成Gist，验证后加入C）。
   - ④ 当队列为空时，生成更多子任务（检查当前状态是否需要新任务）。
   - ⑤ 最终答案生成（从已验证的共享上下文综合答案）。

3. **压缩与验证**：
   - 对于推理轨迹：直接压缩成Gist，验证是否忠实反映发现/失败/约束。
   - 对于长源单元：采用**层次化压缩**：原始内容 → 引用型摘要 Si → 紧凑Gist Gi。验证在两个层级进行：Si 必须有原始引用支持，Gi 必须保持 Si 中的关键信息。
   - 只有通过验证的更新才允许写入C，失败则重写或拒绝。

4. **选择性展开**：
   - 默认只读Gist，需要时通过 `UNFOLD` 请求回到Si，再通过 `DEEP_UNFOLD` 回到原始内容。展开后的内容只对当前调用可见，不写回C，避免污染共享上下文。

5. **依赖感知队列**：任务可标注依赖关系，只有前置完成的任务才能被领取。队列空时触发生成更多子任务逻辑。

### 与集中式系统的对比
- 集中式：主智能体同步 scatter-gather 循环。
- DeLM：智能体异步领取任务，通过共享状态协调，无单一瓶颈。

## 3. 实验设计

## 6. 论文的主要结论与发现

1. **DeLM在测试时扩展上显著优于集中式系统**：
   - SWE-bench Verified上，Avg.@1达65.7%（Gemini 3 Flash），比最强基线AOrchestra-Parallel高9.3个百分点；Pass@4达77.4%。
   - 成本降低约50%（$0.12 vs 基线约$0.24-$0.26）。
2. **共享已验证上下文是关键**：失败的假设、约束、部分解决方案可通过共享状态复用，避免重复劳动，这是集中式系统无法做到的。
3. **DeLM在长上下文推理上有效**：
   - LongBench-v2上，使用四个模型平均准确率均最高，提升最高5.7个百分点（GPT-5.4: 60.1% vs 最优基线54.4%）。
4. **验证和层次摘要均重要**：消融实验显示去掉验证降幅最大（60.1%→55.2%），去掉层次摘要也下降（60.1%→57.7%）。
5. **DeLM与RLM互补**：
   - OOLONG上单独DeLM不如RLM（自然语言共享上下文不适合精确计数），但混合方法DeLM+RLM取得最佳结果（64.0%准确率，成本$0.40），优于两者单独。
6. **紧凑共享机制是成本效率的来源**：通过紧凑Gist传递发现，避免暴露完整轨迹，降低token开销。

## 7. 优点

- **创新性**：首次提出将多智能体协调从中心化路由转为基于共享状态的去中心化设计，明显区别于现有集中式或黑板式方法。
- **可靠性**：引入**准入时验证**机制，确保共享上下文中的信息有证据支撑，防止错误传播，这是核心亮点。

- **实验充分**：多模型、多基准、消融实验、轨迹分析，验证了方法的有效性和各组件贡献。
