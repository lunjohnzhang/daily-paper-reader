## 摘要
自动驾驶系统必须在部分可观测条件下运行，其中安全关键物体可能被遮挡或仅对相邻的网联车辆可见。车对车协作可以减少这种不确定性，但现有的协作驾驶方法通常将多智能体证据压缩为潜在特征或隐藏的多模态状态。因此，它们模糊了每个智能体观察到哪个物体、该物体对自车是否可见，以及冲突证据如何影响下游决策。我们提出G-MARK，一个基于地面的多智能体推理框架，将协作的以物体为中心的观测转换为显式的、可溯源的知识图谱（KGs）。生成的KGs保留了物体假设及其来源归属、自车与合作伙伴的可见性、不确定性、冲突、空间关系和规划相关上下文。G-MARK随后从这些KGs中推导出共享特征表示，使轻量级任务头能够支持物体推理、运动预测、控制选择和轨迹预测。与最先进的基线相比，G-MARK在遮挡推理准确性上提高了42.2%，控制选择误差降低了13.1%，并以25.6倍更小的结构化通信负载实现了相当的轨迹规划准确性。我们的代码可在https://github.com/bhavyagupta98/g-mark获取。

## Abstract
Autonomous driving systems must operate under partial observability, where safety-critical objects may be occluded or visible only to neighboring connected vehicles. Vehicle-to-vehicle cooperation can reduce this uncertainty, but existing cooperative driving methods often compress multi-agent evidence into latent features or hidden multimodal states. As a result, they obscure which agent observed each object, whether the object is visible to the ego vehicle, and how conflicting evidence affects downstream decisions. We propose G-MARK, a grounded multi-agent reasoning framework that converts cooperative object-centric observations into explicit provenance-aware knowledge graphs (KGs). The resulting KGs preserve object hypotheses together with their source attribution, ego-versus-partner visibility, uncertainty, conflicts, spatial relations, and planning-relevant context. G-MARK then derives a shared feature representation from these KGs, enabling lightweight task heads to support object reasoning, motion prediction, control selection, and trajectory forecasting. Compared with the state-of-the-art baseline, GMARK improves occlusion reasoning accuracy by 42.2%, reduces control-selection error by 13.1%, and achieves comparable trajectory-planning accuracy with a 25.6x smaller structured communication payload. Our code is available at https://github.com/bhavyagupta98/g-mark.

自动驾驶系统在真实道路中面临**部分可观测（partial observability）** 的固有问题：安全关键物体可能被遮挡、超出自车传感器视野，或只能被附近网联车辆（connected vehicles）观测到。车对车（V2V）协作是缓解此问题的重要手段，但现有方法存在明显缺陷：

- **信息压缩导致证据结构丢失**：传统协作感知方法通过早期融合、晚期融合或特征级融合（如 Where2Comm、V2X-ViT、CoBEVT）将多智能体证据压成潜在特征图或最终检测结果，丢失了关键元信息——具体是哪个智能体观察到该物体？物体对自车是否可见？证据间的冲突有多大？这些信息对下游安全决策至关重要。
- **可追溯性不足**：语言类协同方法（如 V2V-LLM、V2V-GoT）虽然处理多智能体推理，但中间状态多为提示词、生成文本或隐向量而非结构化的物体级证据，难以支撑安全攸关的决策追溯。
- **目标**：构建一种能显式保留“证据来源”（provenance）的协作推理表示，使每个物体假设都可追溯到其观测来源、可见性状态和规划相关性，同时保持低通信开销与高推理效率。

## 二、方法论：G-MARK 框架

### 2.1 核心设计思想

G-MARK 的核心原则是**任务条件化延迟证据融合（task-conditioned delayed evidence fusion）** ：不把所有智能体的观测立即合并成单一物体列表，而是先构建一个**来源感知的知识图谱（provenance-aware KG）** ，等到下游任务明确后再按需查询相关证据。这种设计避免了过早融合造成的信息不可逆丢失。

G-MARK 运行在感知层之上，不直接处理原始相机或 LiDAR 数据，而是消费已处理的感知输出（检测框、置信度、智能体位姿等）。

### 2.2 四阶段流程

**第一阶段：协作 KG 生成（Cooperative KG Generation）**

每个智能体的本地感知输出被实例化为局部证据图，包含三类节点：

- **智能体节点（agent node）**：存储身份、位姿、时间戳、自车/伙伴角色；
- **观测节点（observation node）**：表示单个本地物体观测，记作 \(o^{(i)}_{t,j} = (x, \tau, c, a_i, t, \eta)\)，其中 x 为位置/包围框，τ 为语义类型，c 为置信度，a_i 为来源智能体，η 为速度等辅助属性；
- **物体假设节点（object-hypothesis node）**：表示关联后形成的共享物体候选。

节点间通过类型化关系（typed relations）连接：`source`（智能体→观测）、`support`（观测→假设）、`spatial relations`（front-of / behind / near 等）、`planning-context`（near-trajectory / path-relevant）、`evidence-consistency`（cooperatively-supported / low-conflict）。

每个物体假设节点 h 定义为：
\[
h = (x_h, \tau_h, c_h, \pi_h, S(h), u_h, \gamma_h, r_h)
\]
其中 \(\pi_h\) 为来源记录（provenance record），S(h) 为支持观测集合，u_h 为不确定性，γ_h 为分歧度，r_h 为规划相关性。

**第二阶段：保守关联（Conservative Association）**

- 使用**确定性门控规则**判断观测对是否可关联：
\[
\delta_t(v^O_p, v^O_q) = \mathbb{1}[\text{type match}(\tau_p, \tau_q) \wedge d(x_p, x_q) < \epsilon_{\tau_p,\tau_q}]
\]
- 要求语义类别严格一致（保守设计，防止行人-车辆等异类误合并）；
- 对门控通过的观测对计算距离归一化亲和度 \(\alpha_{t,pq} = 1 - d(x_p,x_q)/\epsilon\)；
- 关联输出保持完整支持集和来源记录；
- **弱候选保留**：未通过关联门控的观测保留为候选假设（标记更高的不确定性），不被直接丢弃——这是面向安全的设计。

置信度采用有界 noisy-or 聚合：
\[
c_h = 1 - \prod_{v^O \in S(h)}(1 - c(v^O))
\]

**第三阶段：协作上下文丰富（Context Enrichment）**

为每个假设生成增强向量 \(\phi(h) = [\phi_{prov}, \phi_{vis}, \phi_{unc}, \phi_{dis}, \phi_{plan}]\)，涵盖五类信息：

| 类别 | 作用 |
|---|---|
| 来源与支持 | 记录来源智能体、支持数、自车/伙伴/协作状态 |
| 智能体可见性 | 自车相对与智能体相对可见性（visible/occluded/uncertain） |
| 不确定性与可靠性 | 标记弱/模糊/候选假设 |
| 跨智能体分歧 | 记录几何或语义不一致 |
| 规划相关性 | 轨迹距离、运动线索、控制上下文 |

最终的特征向量 \(\psi(h)\) = 物体状态属性 + 增强向量 \(\phi(h)\)。

**第四阶段：统一 KG 任务头（Unified Task Heads）**

三个任务族共享同一 KG 派生特征界面：
- **选择与可见性推理**（Q1-Q4）：检索/排序函数；
- **运动与交互预测**（Q5/Q6/Q7）：轻量级回归头；
- **控制与轨迹规划**（Q8/Q9）：分类/回归头。

推理统一表示为 \(y_k = R_k(G_t, \{\psi(h)\})\)，各任务头可以仅使用轻量 MLP/逻辑回归，无需重型多模态模型，同时保留证据可追溯性。

2. **关联策略偏保守**：确定性门控要求语义类别严格一致，并依赖固定距离阈值 ε，对类别误分类或大姿态误差的鲁棒性不足；动态场景中同一物理物体的类别可能随时间漂移，导致时序关联断裂。
3. **方法对比不够充分**：主结果仅与 V2V-GoT 对比，未与更多传统协作感知模型在相同任务上直接比较；且未报告与端到端协作感知系统在完整感知-推理链路上的联合对比。
4. **轨迹预测性能落后**：Q9 的 L2 误差略逊于 V2V-GoT（-3.4%），表明 KG 在长时程预测任务的表示上仍有改进空间；这也说明“延迟融合”原则并非在所有任务上自动占优。
5. **评估场景单一**：仅在 V2V4Real 基础上的 V2V-GoT-QA 基准上验证，未涵盖恶劣天气、遮挡密集路口或高车流密度等场景，泛化性证据不足。
6. **缺乏不确定性校准分析**：虽然框架中保留了不确定性特征 u_h，但论文未对预测置信度做校准评估（如 ECE），也未将不确定性显式输出给下游规划器用于风险感知决策。
7. **安全保证未形式化**：弱候选保留虽体现了安全导向，但未给出碰撞率、漏检率等安全指标在闭环仿真中的定量验证，暂不能证明“安全性能提升”。

## 九、总体评价与展望

G-MARK 是一篇设计理念清晰、工程实现完整、实验分析扎实的协作驾驶推理论文。其核心贡献不在于提出一个新的感知模型，而在于重新思考了协作信息的表示方式：**用来源感知的知识图谱替代不可逆的特征压缩**，实现了协作全链路证据可追溯、按需查询、高效通信的三重目标。将 9 个异构任务统一到同一 KG 特征界面上，展现了该表示的良好通用性；通信量降低 25.6× 且多数任务精度提升的结果，则有力地支撑了“延迟融合”原则的价值。

对未来工作的自然延伸包括：将关联门控改为可学习或自适应阈值以增强鲁棒性；引入时序图传播以捕获长程动态依赖，改善轨迹预测；在更多基准与真实路测数据上验证泛化性；以及将 KG 推理框架与闭环规划器集成，完成端到端安全评估。

综合来看，G-MARK 在协作驾驶的推理表示设计上提供了有价值的思路：在追求精度的同时，将可解释性、可审计性和通信效率纳入了一体化设计考量。其轻量、结构化、可追溯的特性，使其不仅适用于自动驾驶，也可能为多机器人协作感知、车路协同等更广泛的分布式智能系统提供参考。
