## 摘要
具身智能体AI框架能够解释开放式任务目标，并将其分解为多步计划。关于具身能力、物理前提条件和跨机器人协调的更丰富信息可以改善任务落地，但并不能消除不可行、时机错误或存在安全风险的物理动作。因此，物理机器人团队需要在语义规划与执行之间建立一种明确的架构接口，使得每个规划的动作在执行前都必须根据机器人能力、系统状态和工作流约束进行验证。本文提出了物理具身智能体AI，一种基于技能落地的机器人智能体编排框架，其中每个机器人暴露一个可执行技能的类型化库，而基础模型规划器将任务分解为多个阶段，并将每个阶段分配给一个机器人-技能对。机器人编排层向不执行动作的任务规划器展示技能库、机器人状态、命名位置和工作流契约，而确定性的机器人编排器每次验证并授权一个技能。我们在无人机-无人地面车搜索与派遣任务上进行了评估，每个条件下的每次任务都在Gazebo中实时执行；此外，我们还在人形机器人-四足机器人运输任务上使用了与硬件等效的技能接口，并在Unitree G1和Go2上进行了两次物理试验。通过独立调整规划器知识和运行时强制策略，我们发现检索将技能落地率从51%提升到96%，但仍有23-29%的有信息规划器派遣了故障步骤。每次派遣的强制策略将错误派遣降至0%，且无误拦截；一项保留规划器的消融实验证实，负责这一效果的是门控机制，而非规划变化。实时执行使差异物理化：在没有强制策略的情况下，所有八个注入的故障都越过了编排边界，其中六个产生了机器人运动；而在有强制策略的情况下，所有八个故障在运动前均被拒绝。

## Abstract
Agentic AI frameworks interpret open-ended task goals and decompose them into multi-step plans. Richer information about embodiment-specific capabilities, physical preconditions, and cross-robot coordination improves grounding, but does not eliminate infeasible, mistimed, or unsafe physical actions. Physical robot crews therefore require an explicit architectural interface between semantic planning and execution, where every planned action is verified against robot capabilities, system state, and workflow constraints before actuation. This paper introduces Physical Agentic AI, a framework for skill-grounded robot agent orchestration, in which each robot exposes a typed library of executable skills while a foundation model planner decomposes a task into phases and assigns each phase to a robot-skill pair. A Robot Orchestration layer exposes the skill library, robot state, named locations, and workflow contracts to a non-actuating Mission Planner, while a deterministic Robot Orchestrator validates and authorizes one skill at a time. We evaluate on a drone-UGV search-and-dispatch mission, where every mission in every condition is executed live in Gazebo, and on a humanoid-quadruped transportation task using hardware-equivalent skill interfaces plus two physical trials on a Unitree G1 and Go2. Varying planner knowledge and runtime enforcement independently, we find that retrieval raises skill grounding from 51% to 96% yet leaves informed planners dispatching 23-29% of faulted steps. Per-dispatch enforcement reduces false dispatch to 0% with no false blocks, and a held-plan ablation confirms that the gate, not plan variation, is responsible. Live execution makes the difference physical: without enforcement all eight injected faults crossed the orchestration boundary and six produced robot motion; with enforcement all eight were refused before motion.

## 2. 论文提出的方法论

### 核心思想
采用**知识-强制分离**架构：基础模型只作为高层规划器，在检索到的、已验证的技能库上进行规划；决定“什么可以触碰物理世界”的权力完全归属确定性的机器人编排器（Robot Orchestrator, RO）。

### 关键组件
1. **机器人技能库**：每个机器人暴露一个类型化的可执行技能库，每项技能定义参数、前提条件、预期效果、执行成本和同步要求。
2. **非执行任务规划器（Mission Planner）** ：一个无法直接驱动电机的基础模型智能体，负责理解用户请求、将任务分解为阶段、选择机器人-技能对，并输出结构化计划：
   π = {(ϕ₁, r₁, κ₁), ..., (ϕ_T, r_T, κ_T)}
3. **工作流契约**：声明式的协调规范，编码机器人角色、可接受的技能、排序约束、同步点、参数有效性规则、运行时绑定值（state-bound values）。契约由同一份声明式规范同时渲染为规划器的提示文本和运行时检查器的逻辑。
4. **确定性机器人编排器（RO）** ：非学习型过程化运行时，每次派遣技能前执行五重验证：
   - 技能在该机器人上存在；
   - 参数有效且满足**请求包含性**（用户指定实体/目标不能被悄悄替换为其他值）；
   - 该步骤是工作流契约中下一个授权的转移；
   - 当前机器人状态满足技能与契约前提；
   - 运行时绑定的值在派遣时刻可用且有效。

### 执行协议
检索上下文 → LLM 生成结构化计划 → RO 全局验证（失败允许一次重新规划）→ 逐步执行，每次派遣重新授权并消耗已授权步骤 → 运行期违反被拒绝，执行失败则停止任务并上报。

### 实现
基于 CrewAI 构建，修改以强制规划-执行分离；机器人适配器通过 ROS2 和 Unitree SDK2 将授权技能映射为实体命令。规划器与契约在仿真和真机部署间完全一致。

## 6. 论文的主要结论与发现

- **结论一：落地性（grounding）是检索问题，派遣安全是强制问题。** 注入技能注册表将技能落地率从 51% 提升至 96%（p = 9.7×10⁻⁷），但知识饱和后的非强制方案仍然派遣 23% 的故障步骤，对故障场景的拦截召回率为 0%。
- **结论二：强制是消除错误派遣的必要条件。** RO 将错误派遣降至 0%（p = 5.0×10⁻⁴），对所有 8 个注入故障实现 100% 拦截召回率和精确率，无误拦截。
- **结论三：保留计划消融证实因果性。** 同一份计划经 RO 门控后错误派遣从 25.7%（9/35）降至 0%，证明是门控机制而非规划器变化导致了安全改善。
- **结论四：发现“检索诱导替代”（retrieval-induced substitution）故障模式。** 上下文信息更多后，LLM 从可检测的幻觉（发明不存在的技能）转向看似合理的错误替换（将无效目的地替换为有效的但错误的注册位置），这类错误会绕过静态语法检查，需要通过请求包含性检查拦截。
- **结论五：物理实时执行验证了差异。** 无强制时，全部 8 个注入故障跨越了编排边界，其中 6 个产生了真实机器人运动；有强制时，全部 8 个故障在运动前即被拒绝。

## 7. 优点

- **方法论的清晰分离**：将检索（planner 知道什么）与强制（运行时允许什么）作为正交维度分别操纵，是理解 LLM-机器人系统安全来源的关键实验设计。
- **实时执行验证**：所有仿真任务均实际运行于 Gazebo/PX4 SITL，而非仅做计划合法性检查；真实机器人演示补充了物理有效性。
- **统一的声明式规范**：同一契约规范同时渲染为规划器提示和运行时检查器逻辑，从结构上消除了“模型读到的规则”与“运行时强制执行的规则”不一致的问题。
- **动态绑定处理**：对“规划时不存在、执行时才产生”的运行时值（如无人机感知到的目标坐标）提供了显式的状态接口解析机制，解决了纯提示侧知识无法覆盖的时间性问题。
- **发现并命名了新颖的失败模式**：检索诱导替代（substitution）的定义和检测方法对领域具有普适意义。
- **跨平台可移植性**：规划器和契约在仿真与真机间完全不变，仅替换技能库和适配器，验证了架构的可迁移性。
