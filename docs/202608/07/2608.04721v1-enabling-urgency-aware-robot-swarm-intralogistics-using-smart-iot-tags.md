## 摘要
仓库中的物品在搬运紧急程度上有所不同：易腐货物、药品运输和准时制生产材料必须比其余库存更早送达。去中心化的机器人群体适用于无法承担固定自动化基础设施的仓库，但当前的群体控制器要么对所有物品一视同仁，要么依赖外部调度器来设置优先级，因此紧急物品与普通物品等待时间相同。本文提出了一种群体物流系统，其中每个仓库载具持有一个超低功耗物联网标签，通过蓝牙低功耗广播其物品的紧急程度。机器人直接读取这些广播，并在选择要服务的载具时将紧急程度与行驶距离进行权衡，因此优先级确定发生在物品层面，无需中央调度。该系统在模拟中进行了评估，并在真实机器人和带有物联网标签的载具上进行了验证，与仅基于邻近的基线进行了比较。在实际试验中，优先级对齐度（即紧急物品先被服务的比例）从0.41提高到0.64，第95百分位交付延迟有降低趋势但不显著，吞吐量在基线水平的1.2%以内。在模拟中，收益随系统规模增大而增加：在三种更大的配置中，P95延迟降低了5.2%至11.8%，优先级对齐度提高了41.7%至51.6%。因此，将紧急程度附着在物品本身，使得去中心化群体能够更早地服务时间关键的库存，同时保持使群体系统对仓库自动化具有吸引力的低基础设施要求。

## Abstract
Warehouse items differ in how urgently they must be moved: perishable goods, pharmaceutical shipments, and just-in-time production materials must be delivered sooner than the rest of the stock. Decentralised robot swarms suit warehouses that cannot justify fixed automation infrastructure, but current swarm controllers treat all items alike or rely on an external scheduler to set priorities, so urgent items wait as long as ordinary ones. This paper presents a swarm logistics system in which each warehouse carrier holds an ultra-low-power Internet-of-Things (IoT) tag that broadcasts the urgency of its item over Bluetooth Low Energy (BLE). Robots read these broadcasts directly and weigh urgency against travel distance when choosing which carrier to serve, so prioritisation happens at the item level without central scheduling. The system is evaluated in simulation and validated on real robots and IoT-tagged carriers against a proximity-only baseline. In the physical trials, priority alignment (i.e. proportion of urgent items served first), improved from 0.41 to 0.64, with a nonsignificant trend toward lower 95th-percentile (P95) delivery latency and throughput within 1.2% of the baseline. In simulation, the benefit grew with system size: across three larger configurations, P95 latency fell by 5.2% to 11.8% and priority alignment improved by 41.7% to 51.6%. Attaching urgency to the items themselves therefore allows a decentralised swarm to serve time-critical stock sooner while keeping the low infrastructure requirements that make swarm systems attractive for warehouse automation.

## 2. 方法论：核心思想、关键技术细节与算法流程

### 核心思想
在每个仓库载具（carrier）上安装超低功耗智能物联网标签，通过蓝牙低功耗（BLE）周期性地广播物品的紧急程度、状态和目的地。机器人在探索过程中直接读取这些广播信息，并在本地决策中将**紧急程度**与**行驶距离**进行权衡，无需任何中央调度器。

### 关键技术细节

**（1）智能物联网标签硬件**
- 基于 nRF52833 BLE 系统级芯片定制开发；
- 广播载荷为六字节格式：`[0xFF, 0xFF, urgency, status, destination, ArUco ID]`；
- 紧急程度编码为 0–9 的整数刻度；
- 状态字段区分载具的三种状态：空闲（IDLE）、等待取货（AWAITING PICKUP）、已取货（PICKED UP）；
- 标签配备 E-ink 显示屏，便于人工实时查看和调整优先级；
- 支持通过 BLE GATT 特征远程动态更新优先级。

**（2）机器人控制器**
- 基于行为树（Behaviour Tree）架构，每个机器人独立运行完整状态序列：随机探索 → 选择载具 → 预对接 → 对接并对中 → 运输与释放。
- 机器人通过 ArUco 标记进行载具识别与定位。

**（3）载具选择算法（核心公式）**

机器人 *r* 对载具 *c* 的评分函数为：

```
s(r,c) = u_c × (α + u_d(r,c))
```

其中：
- `u_c ∈ [0,9]`：载具的紧急程度（来自标签广播）；
- `α`：可调紧急权重参数，控制紧急程度与空间临近性之间的权衡；
- `u_d(r,c)`：距离邻近项，计算方式为 `9 × (1 − min(d(r,c)/3.6, 1))`，将欧氏距离映射到 0–9 的区间（与紧急程度同尺度）。

紧急感知模式下，机器人选择评分最高的载具；基线模式下，机器人仅根据 `u_d` 选择最近的可用载具。

### 算法流程（文字描述）
1. 机器人通过随机游走探索环境；
2. 在标签检测范围内（约 3.6m）接收载具的 BLE 广播，获取其 ID、紧急程度、状态和目的地；
3. 机器人根据当前策略（紧急感知或仅邻近）计算所有可用载具的评分；
4. 选择评分最高的载具，使用 ArUco 标记进行精确对接；
5. 提升载具、运输至卸货区、释放载具；
6. 载具状态自动更新（等待取货 → 已取货 → 空闲），防止其他机器人重复选择。

## 3. 实验设计：场景、基准与对比方法

### 实验场景
- **物理环境**：3.75m × 3.75m 的仓库模拟场地，包含取货区和卸货区，使用 3 台 DOTS 机器人（直径 250mm，三向全向轮，最大速度 2m/s，载重 2kg）和 7 个载具，每个载具装有智能 IoT 标签。
- **仿真环境**：自定义 2D Python 仿真器，模拟全向运动、碰撞检测、随机游走探索、受限标签检测范围、取货/交付循环；物理环境与仿真场地尺寸一致。

### Benchmark 与对比方法
- **基线（Baseline）**：仅邻近性（proximity-only）策略，机器人选择最近的可用载具，完全忽略标签广播的紧急程度信息。
- **实验组**：紧急感知策略，使用三种不同的紧急权重参数：`α = 0.7`（轻度）、`α = 3.0`（中度）、`α = 9.0`（重度）。

### 三阶段实验流程
1. **仿真控制器选择**：3 机器人 + 7 载具配置，初步扫描 α 从 0 到 1（步长 0.1），然后对保留的 α 值（0.3、0.5、0.7、0.9）及 α=3.0、9.0 进行评估，最终选出 0.7、3.0、9.0 进行后续测试。
2. **物理实验验证**：3 机器人 + 7 载具，对四种条件（基线 + 三种 α）各进行 15–17 次有效运行。
3. **仿真可扩展性分析**：3 种规模——5 机器人/10 载具、10 机器人/20 载具、20 机器人/40 载具，每配置对比基线 vs. α=0.7。

### 评估指标
- **P95 延迟（P95 Latency）**：第 95 百分位数的单次载具交付延迟；
- **平均延迟（Mean Latency）**：所有交付的平均延迟；
- **吞吐量（Throughput）**：单位时间内交付的载具数量；
- **优先级对齐度（Priority Alignment, PA）**：在最高紧急程度的前 x% 载具中，有多少比例被包含在最快完成交付的前 x% 中（x 从 5% 到 50%）。

## 6. 主要结论与发现

1. **物理实验（RQ1）**：紧急感知策略显著提升了优先级对齐度——在 α=0.7 时从 0.41 提升至 0.64（+0.22，p < 0.01），同时吞吐量维持在基线水平的 1.2% 以内；P95 延迟有 9.1% 的下降趋势但未达统计显著。
2. **可扩展性（RQ2）**：系统规模越大，收益越明显——三组更大配置下，P95 延迟降低 5.2%–11.8%，优先级对齐度提升 41.7%–51.6%；小规模下的吞吐量损失（−9.4%）在大规模下消失，表明紧急优先的代价随群体规模增加而被摊薄。
3. **权重权衡（RQ3）**：α 的探索揭示了紧急响应与空间效率之间的权衡——过强的紧急权重（α=9.0）虽然最大化优先级对齐度，但会损害平均延迟和吞吐量；仿真偏好较强权重（α=9.0），物理平台偏好较轻权重（α=0.7），差异可能源于仿真中未建模的机器人间交互、定位不确定性和拥塞效应。
4. **总体结论**：将紧急程度附着于物品本身（而非中央调度），使得去中心化群体能够在保持吞吐量和低基础设施要求的同时，更及时地服务时间关键的物品。

- **系统完整度高**：从硬件（定制 IoT 标签）到软件（ROS 2 + 行为树控制器 + 自定义 BLE 库）实现了完整闭环，并完成了从仿真到物理平台的验证链条。

## 8. 不足与局限

- **物理实验规模有限**：仅 3 台机器人和 7 个载具、15–17 次有效运行/条件，统计功效不足，P95 延迟改善未能达到显著水平；更大的物理验证仍有待进行。

- **场景简化程度较高**：物理场地仅 3.75m×3.75m，未涉及真实仓库的复杂布局（货架、走廊、多区域）、更长的运输路线或更密集的障碍物；未考虑多机器人争抢同一载具的冲突消解（虽有状态字段但未专门分析行为模式）。
