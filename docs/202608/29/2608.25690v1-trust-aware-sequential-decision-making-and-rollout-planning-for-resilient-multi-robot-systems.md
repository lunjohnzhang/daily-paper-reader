## 摘要
多机器人系统中的序贯决策通常假设规划信息可靠，且智能体执行规划器预期的动作。被破坏的智能体可能违反这两种假设，导致规划模型与物理执行之间出现不匹配。我们在定位欺骗下的在线多机器人路由中研究这一问题。我们引入了一种针对监控者感知型对手的距离约束欺骗模型，以及一种分层二部匹配策略，该策略在限制欺骗幅度的同时最大化分配影响力。为缓解此类攻击，我们开发了一种信任感知监控器，将概率定位信任（使用真实GPS欺骗数据校准）与任务执行中的行为证据相结合，以对智能体进行分类，并在后续规划中移除已检测到的对手。我们进一步表明，未被检测到的对手可能通过违反规划器-执行一致性，导致滚动规划失去其预期成本改进行为。信任感知移除可在检测后恢复这种一致性，从而实现稳定的路由，并恢复滚动规划相对于基础策略的经验优势。使用真实GPS欺骗数据集和旧金山出租车需求进行的实验表明，在各种欺骗能力、对手车队规模、自适应攻击、监控配置和滚动时域下，该方法均能实现有效检测和弹性路由。

## Abstract
Sequential decision-making in multi-robot systems typically assumes that planning information is reliable and that agents execute the actions anticipated by the planner. Compromised agents can violate both assumptions, creating a mismatch between the planning model and physical execution. We study this problem in online multi-robot routing under localization spoofing. We introduce a distance-constrained spoofing model for monitor-aware adversaries, together with a tiered bipartite matching strategy that maximizes assignment influence while limiting spoofing magnitude. To mitigate such attacks, we develop a trust-aware monitor that combines probabilistic localization trust, calibrated using real GPS spoofing data, with behavioral evidence from task execution to classify agents and remove detected adversaries from subsequent planning. We further show that undetected adversaries can cause rollout to lose its expected cost-improvement behavior by violating planner-execution consistency. Trust-aware removal restores this consistency after detection, enabling stable routing and recovery of rollout's empirical advantage over the base policy. Experiments using real GPS spoofing datasets and San Francisco taxicab demand demonstrate effective detection and resilient routing across varying spoofing capabilities, adversarial fleet sizes, adaptive attacks, monitoring configurations, and rollout horizons.

## 二、论文提出的方法论

### 1. 整体框架：信任感知序贯规划（Trust-Aware Sequential Planning）

论文提出一个三层闭环架构：

- **信息评估（Information Assessment）**：从两类可观测信号中生成可靠性证据：
  - **定位信任（Localization Trust）**：基于真实GPS欺骗数据校准的概率模型，评估智能体报告位置的可靠性。
  - **行为信任（Behavioral Trust）**：基于任务执行结果（成功取件、请求过期、重复分配等）评估智能体的服务行为是否符合协作预期。
- **信任感知状态构建与规划（Trust-Aware State Construction & Planning）**：根据融合后的信任分类 χi(t)∈{C,S,A}（协作、可疑、对抗），过滤掉被判定为“对抗”的智能体，构造可信规划状态（trusted planning state），再调用底层规划策略（如IA-RA或rollout）进行决策。
- **执行（Execution）**：物理系统执行命令后，产生新的观测（如取件成功/失败、请求取消等），作为下一轮信任更新的证据。

核心闭环流程为：  
**观测 → 信任更新 → 可信规划状态 → 规划 → 执行 → 新观测**

### 2. 威胁模型：监控者感知的距离约束欺骗（Monitor-Aware Distance-Constrained Spoofing）

- 攻击者模型的5项基本能力（定义1）：可篡改位置报告、不可创建Sybil身份、可能拒绝服务、了解路由策略与分配机制、可与其他对手协调。
- **距离约束**（定义3）：对手报告位置必须在真实位置周围图距离 dmax 以内，即 v̂at ∈ Bat(dmax)。dmax 越小，欺骗越隐蔽但影响力受限；dmax ≥ D(G) 时退化为无约束欺骗。
- **分层目标优先级**：对手只针对“协作可达”的请求（即存在协作智能体能在请求过期前到达其取件点的请求），并按“距离协作服务最近的程度”分层（tier）。攻击按三重字典序优化：
  1. 最大化可同时干扰的请求数；
  2. 优先干扰更接近被协作智能体服务的请求；
  3. 在同等条件下最小化总欺骗位移。
- 该问题可转化为加权二部匹配问题，通过引入足够大的权重系数 βt、κt 保证字典序优先级。

### 3. 信任证据机制

**定位信任：**
- 使用真实GPS欺骗数据集，提取信号特征（伪距一致性、多普勒、载噪比、载波相位连续性、卫星可用性、精度因子、导航误差等）。
- 用高斯混合类条件分布 + 二次判别分析（QDA）得到后验置信分数，再对每类分数拟合Beta分布。
- 在线运行时，根据归一化定位偏差 Δi,t 在协作分布与对抗分布之间插值（均值和方差），并通过矩匹配得到Beta参数。
- 滑动窗口（Wloc=67）聚合后，与阈值 κloc_adv、κloc_coop 比较，产生局部分类。

**行为信任：**
- 每个请求维护完整的分配历史：谁在何时被分配、预计取件时间、何时被重新分配等。
- 请求终止（成功取件或过期）后，进行责任归因：
  - 成功取件 → 服务智能体获得正向证据；
  - 请求过期 → 最后被分配的智能体获得过期惩罚；
  - 请求过期或被重新分配前，预测取件时间已过但未服务的智能体获得“反复分配扰动”惩罚。
- 行为信任参数 αbeh、βbeh 通过加权累积更新，基于Beta后验均值与置信度阈值进行分类。

**融合规则：**
- 任一分支判定为“对抗”→ 最终为对抗；
- 两个分支均为“协作”→ 最终为协作；
- 其余情况 → 可疑。

**执行规则**：被判定为“对抗”的智能体被永久从规划集合中移除，其未完成的分配被撤销，请求历史保留用于后续行为归因。

### 4. 信任感知的Rollout规划

- 基础策略为 IA-RA（Instantaneous Assignment with Reassignment，即时分配与重分配），以最小化“智能体到取件点距离 + 取件点到送件点距离”的二部匹配成本。
- Rollout采用**one-at-a-time（逐个改进）** 策略：以IA-RA解为初始联合动作，逐个智能体在有限动作集合中搜索使蒙特卡洛期望成本最低的动作，其余智能体动作保持固定。
- 使用 H 步前瞻、M 个蒙特卡洛需求场景，阶段成本为当前未完成请求数 + 累计过期请求数。
- 关键理论分析：若对抗智能体未被检测出（At+≠∅），rollout的仿真模型假设其执行命令，但物理执行并非如此，导致成本估计失真、滚动规划丧失成本改进属性；信任感知移除后（At+=∅），规划与执行重新对齐。

- **无监控的Rollout**：使用IA-RA作基础策略，但对手在前瞻仿真中被当作协作资源。

- **信任感知Rollout（Trust-Aware Rollout）**：检测到的对手被移除后，对可信规划状态执行one-at-a-time rollout。

### 3. 消融与变量

- **监控器消融**：仅定位信任 vs. 仅行为信任 vs. 融合监控器。
- **欺骗范围**：dmax ∈ {0.1D(G), 0.5D(G)}。
- **对手比例/数量**：若干种初始对手数量与规模。
- **Rollout参数**：默认 H=10、M=100；另评估 (20,200) 和 (30,300)。
- **协作车队规模**：35个（最小稳定规模）与49个（更高容量）。
- **评估指标**：待处理请求数、累计取消请求数、路由成本（待处理+累计取消）、检测出的对手数、仍在活动的对手数、协作智能体误报数、检测时间。

## 六、论文的主要结论与发现

1. **单个对抗智能体即可破坏名义稳定的车队**：在IA-RA策略下，即使只有一个对手，只要欺骗范围足够宽，就能导致系统失去稳定性（待处理请求与取消请求持续累积）。
2. **距离约束欺骗造成影响力-可检测性权衡**：对手通过限制欺骗距离可以保持对路由的显著干扰，同时使定位信任与协作分布更难区分。
3. **定位信任与行为信任具有互补性**：定位信任能较早期识别大幅欺骗，但在小偏差攻击下失效；行为信任虽然检测较慢，但不受欺骗幅度限制，能识别定位证据模糊的对手。融合监控器取得最低路由成本和最少残余对手，同时保持极低的误报率。
4. **未被检测的对手会破坏rollout的成本改进属性**：由于前瞻仿真将对手视为协作资源，而实际执行并非如此，rollout可能表现得比其基础策略IA-RA更差。
5. **信任感知移除可恢复规划-执行一致性**：移除被检测的对手后，滚动规划的仿真模型与执行车队重新对齐，在足够的规划时域和车队容量支持下，rollout可以恢复稳定路由并重新获得优于基础策略的经验优势。
6. **恢复能力取决于规划时域与车队容量**：短时域（H=10）即使在监控下仍可能不稳定；更长的前瞻（H=20、30）与更高的协作车队容量（49个智能体）能更有效地清除检测延迟期间累积的积压需求。

## 七、优点

1. **问题建模具有深度**：论文清楚地区分了“感知状态”与“真实状态”、“命令动作”与“执行动作”，系统性地刻画了规划-执行不匹配的数学结构，抓住了安全决策问题的本质。
2. **信任-规划闭环设计新颖**：将信任从“检测分数”提升为“规划状态构造机制”，使信任直接改变规划器所作用的智能体集合，而非停留在报警层面。这一抽象具有通用性，可推广到模型预测控制、近似动态规划等其他模型基序贯决策方法。
3. **威胁模型贴合实际**：距离约束欺骗模型考虑了监控者感知型对手的现实约束，攻击策略通过分层二部匹配精细化地权衡影响力和可检测性，使压力测试更真实、更具挑战性。
4. **多源信任证据设计合理**：定位信任（信息层）与行为信任（执行层）的互补设计针对了不同攻击模式，且有真实GPS数据校准作为基础，而非凭空设定。
5. **实验设计较为系统**：消融实验覆盖了监控器各组件、欺骗范围、对手规模、规划时域与车队容量等多个维度，能有力支撑主要结论。

## 八、不足与局限

1. **威胁模型的适用范围有限**：
   - 未考虑Sybil攻击（伪造身份）；
   - 未考虑间歇性身份变化；
   - 未考虑对中央监控器本身的攻破；
   - 未考虑“部分合规”的对手——即混合执行部分任务以操纵行为信任的策略性对手。
2. **定位信任依赖外部独立参考**：在线部署中需要独立的定位完整性机制或可信参考源，而论文在仿真中直接用真实位置生成偏差。外部参考源本身可能失效或被攻击，这一问题未深入讨论。
3. **行为归因的歧义性**：请求过期、分配扰动可能由拥堵、硬件故障、通信中断等非对抗因素引起，现有责任归因规则无法区分这些原因，可能导致误判。
4. **永久移除策略过于生硬**：被判定为对抗的智能体被永久移出规划，未考虑临时隔离、可逆进入、信任约束下的降级使用等更精细的干预手段。在误报情况下永久移除会浪费车队容量。
5. **缺乏理论保证**：论文明确承认其稳定性与rollout改进结果均为经验性的。未给出检测时间界、闭环稳定性条件或信任分类精度与系统性能之间的定量关系。
6. **实验覆盖仍有限**：单一城市路网、单一需求数据源，对手行为模式相对固定，未验证框架在更广泛地理与交通条件下的泛化性能。
