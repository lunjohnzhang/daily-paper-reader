## 摘要
基于LLM的多智能体协调在动态环境中面临效率与适应性之间的根本性权衡。现有方法通常依赖重复的LLM调用或多轮通信来在执行过程中调整决策，这会引入大量延迟，并使协调容易受到异步进展和环境变化的影响。相反，一次性规划降低了协调开销，但产生的开环计划可能迅速过时，或在动作依赖其他智能体和环境时失败。我们提出SyncPlan，一种通过显式同步和自适应校正实现长时程协调的计划-执行-校正框架。给定状态和团队级任务，集中式LLM协调器在单次规划调用中生成每个智能体的动作链。在执行过程中，显式等待原语和死锁检测强制执行智能体间以及智能体-环境之间的依赖关系，同时轻量级计划陈旧性检测器持续评估剩余计划，并在环境变化使其假设失效时触发重新规划。我们进一步通过SFT和面向规划的RL，结合密集任务进展和结果级执行反馈来优化协调器。在公共Overcooked基准和复杂的Honor of Kings环境上的实验表明，与现有基于LLM的协调器相比，SyncPlan实现了最先进的任务成功率，同时使用的墙钟运行时间不到其0.05%。代码和数据集将公开发布。

## Abstract
LLM-based multi-agent coordination faces a fundamental trade-off between efficiency and adaptivity in dynamic environments. Existing approaches typically rely on repeated LLM invocations or multi-round communication to adapt decisions during execution, introducing substantial latency and making coordination vulnerable to asynchronous progress and environmental changes. Conversely, one-shot planning reduces coordination overhead but produces open-loop plans that can quickly become stale or fail when actions depend on other agents and the environment. We introduce SyncPlan, a plan-execute-correct framework for long-horizon coordination through explicit synchronization and adaptive correction. Given the state and team-level task, a centralized LLM coordinator generates per-agent action chains in a single planning call. During execution, explicit wait primitives and deadlock detection enforce inter-agent and agent-environment dependencies, while a lightweight Plan Staleness Detector continuously assesses the remaining plan and triggers replanning when environmental changes invalidate its assumptions. We further optimize the coordinator through SFT and planning-oriented RL with dense task progress and outcome-level execution feedback. Experiments on the public Overcooked benchmark and the complex Honor of Kings environment show that SyncPlan achieves state-of-the-art task success rates while using less than 0.05% of the wall-clock runtime compared with existing LLM-based coordinators. Code and datasets will be made publicly available.

- **根本矛盾**：LLM 驱动的多智能体协调在动态环境中面临**效率与自适应性**的根本权衡。

  - **一次性开环规划**效率高，但计划容易因环境变化而失效，且无法处理智能体间的时序依赖。
- **核心问题**：如何在动态、异步执行的环境下，让 LLM 协调机制同时做到高效、同步、自适应？
- **具体挑战**（作者归纳为三个）：
  1. **实时性约束**：环境按帧演化，LLM 调用开销难以满足响应时间预算；
  2. **计划过时**：环境变化使旧计划失效，周期重规划浪费计算且反应迟缓；
  3. **协调冲突**：LLM 的自由文本计划难以表达可验证、可执行的智能体间依赖关系。

### 2. 方法论：SyncPlan 框架

SyncPlan 是一个**计划–执行–校正**（Plan-Execute-Correct）三阶段框架，核心思想是将规划与执行分离，以显式同步保证协调正确性，以轻量检测触发按需重规划，以训练优化提升规划质量。具体组件如下：

#### （1）协作规划（Collaborative Planning）
- 由**集中式 LLM 协调器**在**单次规划调用**中为 N 个智能体生成完整动作链：`Π_t = D_θ(s_t, e) = {π^1_t, ..., π^N_t}`，每个 `π^i_t` 为长度 L 的动作序列。
- 引入**可执行同步原语**（灵感来自操作系统中的进程同步）：
  - `Wait_agents(a, m, s)`：等待另一智能体到达指定里程碑（启动或完成）；
  - `Wait_entity(e, attr, op, v)`：等待环境实体属性满足特定条件。
  - 将隐式自然语言协调意图（如"等队友到了再上"）转化为**机器可检查的显式约束**。

#### （2）运行时执行（Runtime Execution）
- 每个智能体维护一个执行指针 `h_i`，逐帧推进自身动作链；同步原语只阻塞对应智能体，不阻塞他人。
- **死锁检测**：维护有向等待图，当 `Wait_agents` 依赖形成**有向环**时判定死锁并触发重规划，采用增量可达性检验（O(K) 复杂度）保证执行效率。

#### （3）自适应校正（Adaptive Correction）
- **计划陈旧性检测器（PSD）**：轻量二分类模型，输入三元组：
  - 链-实体关联矩阵 `C_t ∈ {0,1}^{N×M×L}`（标记动作链引用了哪些实体）；
  - 当前实体状态矩阵 `X_t ∈ [0,1]^{M×F}`；
  - 状态差分矩阵 `Δ_t ∈ [−1,1]^{M×F}`（与 k_ref=3 帧前的差异）。
  - 采用双线性通路（链通路 + 状态通路）建模，输出重规划概率 `P_replan(t)`，超过阈值 η=0.7 时触发按需重规划。
- 与固定频率重规划相比，PSD 实现**事件驱动**校正——"何时纠正比多久纠正一次更重要"。

#### （4）SFT + 面向规划的 RL 两阶段训练
- **SFT**：用专家轨迹和蒸馏协调数据构造指令对，赋予协调器结构化输出能力和同步原语使用先验（LoRA 微调）。
- **RL（GRPO）**：以执行反馈为奖励，优化完整动作链。复合奖励函数为：
  `R(A) = R_prog(A) + α·1[Ω(A)=Success] − (P_syn + P_sem + P_dlk + P_tmo)`
  - `R_prog` 融合三个分量：链内完成比例（`w_frac=0.15`）、效率（`w_eff=0.15`）、长度正则（`w_len=0.25`）；
  - 结果级惩罚按严重度排序：死锁 1.0 > 语义错误 0.3 > 语法错误 0.1 > 超时 0.0；成功奖励 α=0.45。
  - 五类终止结果：Success、SyntaxError、SemanticError、Deadlock、Timeout。

### 6. 主要结论与发现

1. **效果显著**：Overcooked 上比最强 LLM 基线平均 TAR 提升 12.2 个百分点；HoK 上达到 86.3% TAR，超过 DPT-Agent 17.6 个百分点。
2. **效率极高**：墙钟运行时间仅为现有 LLM 协调器的 **0.05%** 以下（HoK 上 RTR 0.83x vs 基线 15~23x），实现 5v5 MOBA 实时协调。
3. **PSD 价值得到验证**：移除 PSD 在动态场景 TAR 下降 8+ 点；固定频率重规划（4/8FPS）大幅增加延迟却无正向收益，说明**按需检测优于固定频率**。
4. **RL 是必要的**：SFT-only 协调器虽能生成语法正确的计划，但缺乏执行时序对齐；RL 通过闭环反馈显著提升 TAR（如 HoK 79.0%→86.3%），并降低死锁率与 ATR。
5. **模型规模存在临界阈值**：1B 以下模型无法稳定生成结构化动作链；3B 以上性能提升趋于平缓（结构化 schema 限制了额外容量的收益）。

### 7. 优点

- **思想清晰且工程可落地**：将操作系统中的同步机制（wait 原语、死锁检测）引入 LLM 规划，把不可靠的隐式自然语言协调转化为可执行、可验证的显式约束，这个跨域借鉴非常巧妙。
- **轻量化的自适应机制**：PSD 为仅几十万参数的小模型，避免高频 LLM 调用，在效率与适应性间取得好的平衡。
- **训练设计完整**：SFT 提供结构化先验，RL 提供执行级反馈，两者互补；复合奖励覆盖任务效果、执行正确性、运行效率三维目标。
- **实验丰富度高**：双平台验证（合作烹饪 + 复杂 MOBA）、多布局/多设置/多模型规模/多 backbone 的系统评估，消融实验设计整洁。
- **效率优势极其突出**：比重复调用式方法低 2-3 个数量级的运行开销，具备实时部署潜力。
- **隐私与数据规范**：HoK 数据来自匿名化真实对局记录，声明无个人身份信息。
