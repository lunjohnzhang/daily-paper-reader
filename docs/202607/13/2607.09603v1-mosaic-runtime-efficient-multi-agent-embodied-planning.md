## 摘要
基于大语言模型的多智能体具身规划因执行延迟过高而仍不实用。我们识别出失败动作是主要瓶颈，源于两个核心挑战：部分可观测性下的不准确状态跟踪，以及产生冗余或冲突动作的低效协调。我们提出Mosaic，一个运行时高效的多智能体规划框架，解决了这两个挑战。Mosaic通过以智能体为中心的语义记忆维护准确而轻量的状态跟踪，该记忆以相对坐标存储物体，支持几何变换与协调。它通过整数线性规划在每一步规划中分配动作，强制执行物理可行性与智能体间协调约束，确保高效协调。在AI2-THOR和搜索救援基准测试中，Mosaic实现了执行速度提升27–32%、大语言模型调用减少30–33%、步数减少25–31%、成功率提高4–10个百分点。这些结果表明，高效记忆与约束引导的协调对于可扩展、低延迟的多智能体规划至关重要。

## Abstract
LLM-based multi-agent embodied planning remains impractical due to prohibitively high execution latency. We identify failed actions as the dominant bottleneck, stemming from two core challenges: inaccurate state tracking under partial observability and inefficient coordination that produces redundant or conflicting actions. We introduce Mosaic, a runtime-efficient multi-agent planning framework that addresses both challenges. Mosaic maintains accurate yet lightweight state tracking through agent-centric semantic memory that stores objects in relative coordinates, enabling geometric transformations and coordination. It ensures efficient coordination through Integer Linear Programming that allocates actions at every planning step, enforcing physical feasibility and inter-agent coordination constraints. Across AI2-THOR and search-and-rescue benchmarks, Mosaic achieves 27-32% faster execution, 30-33% fewer LLM calls, 25-31% fewer steps, and 4-10% points higher success rates. These results demonstrate that efficient memory and constraint-guided coordination are critical for scalable, low-latency multi-agent planning.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：基于大语言模型（LLM）的多智能体具身规划面临**过高的执行延迟**，导致实际部署不可行。作者识别出**失败动作**是主要瓶颈，其根源在于两个挑战：
  1. **部分可观测性下的状态跟踪不准确**：LLM 难以维护关于物体位置的准确信念，导致重复探索或导航到过时位置。
  2. **多智能体协调低效**：任务分配粗粒度、缺乏动作级合理性推理，产生冗余、冲突或违反前置条件的动作。
- **整体含义**：若不能有效减少失败动作及其引发的重规划、空闲等待等连锁成本，LLM 驱动的多智能体系统将无法满足资源受限或时间关键型应用（如搜索救援、家居整理）的实时性要求。论文旨在通过**轻量级内存**与**约束优化**从根本上提升运行时效率。

## 2. 论文提出的方法论

### 核心思想
Mosaic 框架由两个关键设计组成，分别解决状态跟踪与协调问题：
- **智能体中心语义记忆（Agent-centric Semantic Memory, ASM）**：以智能体自身为参考系，存储任务相关物体的**相对距离与方向**，并随智能体运动更新，实现轻量级空间推理和跨智能体信息共享。
- **基于整数线性规划（ILP）的动作选择**：每规划步从 LLM 为每个智能体生成的候选动作中，通过 ILP 选出全局一致的联合动作，强制执行物理可行性、资源互斥、碰撞避免等约束，并通过成本函数最小化冗余与负载不均。

### 关键技术细节

#### (a) 智能体中心语义记忆（ASM）
- 每个物体 `o` 相对智能体 `a` 的距离 `r_{a,o} = (|Δx|+|Δz|)/u`，方向 `φ_{a,o} = atan2(Δx, Δz) - θ_a`（其中 `u` 为单位步长）。
- 智能体移动时根据运动学自动更新相对坐标；若物体离开视野，通过运动历史推断其位置。
- 跨智能体转换：通过智能体间相对距离和方向，利用几何变换将物体坐标从甲智能体框架转换到乙智能体框架，避免重复探索。
- 接口层：连续坐标离散化为语义层级（如“恰好在前面”、“远左侧”），但底层保留连续值，避免累积离散误差。

#### (b) 动作选择的约束优化（ILP 框架）
- **输入**：LLM-Actor 为每个智能体 `a_i` 生成候选动作集 `X_{i,t} = {x^{(1)}_{i,t}, x^{(2)}_{i,t}, ...}`。
- **决策变量**：二进制变量 `z^{(k)}_{i,t}` 表示是否选择第 `k` 个候选。
- **约束**（见表1）：
  - 资格约束：排除物理不可行的动作（如空手时不能放下物体）。
  - 每个智能体每步恰好执行一个动作（包括 no-op）。
  - 多智能体联合子任务需求：如需要两个智能体同时搬运的物体，必须选满人数。
  - 资源独占性：同一物体/插座不能同时被多个智能体操作。
  - 碰撞/干扰避免：互斥的动作候选不能同时选择。
- **成本函数**（公式1）：
  ```
  J = Σ_i Σ_k z^{(k)}_{i,t} [ C_penal(ai, x, H) + λ_load C_load(ai, x, H) ]
  ```
  - `C_penal` 惩罚时空低效行为：循环动作、重复失败、振荡、回溯、停滞，每种模式有对应权重。
  - `C_load` 惩罚负载不均衡：通过比较智能体历史活跃动作数与团队平均值，鼓励空闲智能体参与。

#### 算法流程
采用“集中式规划”架构，每步循环：LLM-Planner 分解子任务 → LLM-Actor 为每个智能体生成候选动作 → ILP 求解器选取全局最优联合动作 → 并行执行 → LLM-Verifier 验证子任务完成 → 更新内存与历史。其中 ILP 求解仅占总体运行时间的 1-2%。

## 3. 实验设计

## 6. 论文的主要结论与发现

1. **失败动作是高延迟的主因**：基线中 16-51% 步数为失败动作，Mosaic 通过 ASM+ILP 减少 7-12 个百分点，从而直接降低运行时。
2. **ASM 与 ILP 互补且可组合**：单独添加 ASM 降低失败率 3 个百分点，单独添加 ILP 降低 4-8 个百分点，二者结合（Mosaic）可获得累计收益。
3. **执行效率大幅提升**：相对最强基线 LLaMAR，AI2-THOR 上运行时减少 **26.9%**，LLM 调用减少 **33.3%**，智能体步数减少 **31.0%**；SAR 上分别为 **31.9%**、**30.2%**、**25.1%**。
4. **任务成功率稳步提高**：AI2-THOR 上成功率提升 **10 个百分点**（0.59→0.69），SAR 提升 **4 个百分点**（0.55→0.59）。
5. **ILP 开销极小**：即使 8 个智能体，ILP 求解时间仅占总运行时的 **1.9%**，可忽略。
6. **跨模型鲁棒**：在 GPT-4o、Claude、Gemini 上均取得一致改进，表明方法不依赖特定模型能力。
7. **噪声下仍有效**：高噪声下成功率降至 0.32（无噪声 0.70），但运行时上升 88%，说明系统主动增加协调努力而非简单崩溃。

## 7. 优点

- **原理明确，设计简洁**：将状态跟踪与协调两个核心挑战分别用轻量级记忆和成熟优化工具解决，可解释性强。
- **运行时高效**：不仅降低失败率，还通过成本函数主动抑制无关动作，实现端到端运行时的显著降低。
- **可扩展性好**：ILP 求解时间随智能体数增长平缓（8 智能体仅 5.87s），且通过动作剪枝（K=3）保持可控。
- **即插即用**：ASM 和 ILP 可作为独立模块插入现有 LLM 规划框架（如 ReAct、LLaMAR），无需修改 LLM 本身。
- **无差别模型适应**：在多个商业 LLM 上均验证成功，降低了部署对新模型调优的依赖。
- **实验设计严谨**：提供了全面消融、超参数分析、噪声鲁棒性、扩展性分析，结果可靠。

## 8. 不足与局限

1. **定位精度依赖**：ASM 依赖相对准确的自身位姿估计。虽然作者评估了中等噪声，但严重传感器漂移或执行器错误（如滑移）可能影响推理。论文承认需低层控制配合，但未在真实机器人上验证。
2. **约束固定，缺乏适应性**：可行性约束需手动编写，可能无法覆盖所有动态或社交行为（如礼貌让路），扩展新场景需领域专家重新定义。
3. **候选动作覆盖可能不足**：若 LLM-Actor 未能生成必要的候选动作（如遇到未见障碍需绕行），ILP 无法补偿。虽然通过 ASM 引导提示可缓解，但根本上受限于 LLM 的生成质量。
4. **实验环境限制**：仅限模拟器（AI2-THOR 和 SAR 网格），未在真机或更复杂的 3D 室内外环境测试，结论向现实世界迁移性未知。
5. **评估规模偏小**：每个任务仅 3 个 episode，虽然方差较小，但任务总数（36+几类）对于多智能体规划基准而言仍显有限。未在更大型、更长时间范围的任务（如整栋楼探索）上验证。
6. **未对比端到端学习基线**：仅对比了纯 LLM 规划方法，未与强化学习（如值分解、经验回放）或混合方法对比，对于更广泛的机器人规划领域而言，基线选择偏窄。
7. **计算资源报告不足**：虽给出 CPU 型号和 RAM，但未提及 API 调用的具体延迟分布，亦未说明 LLM 服务的后台基础设施，不利于复现。
8. **潜在偏差风险**：所有实验由论文作者执行，未提及独立第三方复现。超参数（如成本函数权重 λ 值）通过消融选择，可能存在过拟合任务集的隐患。
