## 摘要
机器人细胞仓库系统（RCWS）引发了多智能体取送货（MAPD）过程，其中机器人按顺序为每个订单收集多个库存单位（SKU）。与假设静态任务的经典MAPD公式不同，真实的仓库操作通常涉及动态订单演化，即在订单执行过程中可能会追加新的SKU。受此实际需求驱动，本文首次提出了考虑内部订单演化的动态多智能体取送货问题。基于令牌传递范式，我们提出了两种事件触发的在线重规划算法。第一种是动态令牌传递，通过添加订单分解和基于优先级的令牌调度，在订单更新时进行局部重规划，同时保持无碰撞执行。第二种是协作令牌传递，进一步使得空闲机器人能够机会性地协助新添加的取货任务，提高系统级效率。在RCWS环境中的仿真结果表明，与静态和非协作基线相比，所提出的方法显著减少了订单流时间。

## Abstract
Robotic Cellular Warehousing Systems (RCWS) give rise to multi-agent pickup and delivery (MAPD) processes in which robots sequentially collect multiple stock-keeping units (SKUs) for each order. Unlike classical MAPD formulations that assume static tasks, real warehouse operations often involve dynamic order evolution, where new SKUs may be appended to an order while it is being executed. Motivated by this practical requirement, this letter formulates the Dynamic Multi-Agent Pickup and Delivery problem considering internal order evolution for the first time. Building on the token passing paradigm, we propose two event-triggered online replanning algorithms. The first, Dynamic Token Passing, performs localized replanning upon order updates through add-order decomposition and priority-based token scheduling while preserving collision-free execution. The second, Cooperative Token Passing, further enables idle robots to opportunistically assist newly added pickups, improving system-level efficiency. Simulation results in RCWS environments demonstrate that the proposed methods significantly reduce order flowtime compared with static and non-cooperative baselines.

## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程
- **核心思想**：在经典令牌传递（TP）框架基础上引入**事件触发机制**——仅当订单更新事件发生时才触发重规划，而非持续重规划。利用单个全局令牌协调多机器人，并在令牌中存储所有机器人当前保留路径、任务分配和截止时间信息。提出两种模式：
  - **绑定模式（Binding Mode）**：每个订单永久绑定给一个机器人，新增SKU必须由同一机器人收集（Dynamic Token Passing, D-TP）；
  - **合作模式（Cooperative Mode）**：允许空闲机器人临时协助处理新增SKU，若能使预计完成时间更短则启用合作（Cooperative Token Passing, C-TP）。
- **关键技术细节**：
  - 动态模型：每个订单可接收最多一次SKU追加；追加事件服从伯努利分布，追加数量随机，位置按空间分布采样。
  - 截止时间优先级：计算**剩余截止时间** Δdₖ(t) = dₖ - t，作为订单紧迫性指标，用于决定重规划优先级（越紧迫越优先获得令牌）。
  - 路径规划：底层采用A*搜索于时间扩展网格图，将令牌中其他机器人的时空占用视为动态障碍物。
  - 两种路径生成函数：**PATH1**：尝试生成完整路径（访问所有剩余+新增SKU后送货）；**PATH2**：若完整路径不可行，生成到安全端点的部分路径，并将未完成任务保留在系统中等待后续重规划。
- **算法流程概要**：
  - **D-TP**：监控订单更新→构建更新订单集及其紧迫度→按剩余截止时间升序入优先队列→依次获取受更新影响的机器人令牌→机器人从当前位置重规划→提交新保留路径→释放令牌→所有机器人同步执行保留路径。
  - **C-TP**：订单更新时，识别绑定机器人ai和空闲机器人集A_idle→计算ai独自完成所有（剩余+新增）的预计时间ETA_base，以及ai只完成剩余的预计时间ETA_rem→对每个空闲机器人aj计算其完成新增SKU并送货的预计时间ETA_add→若存在aj*使得max(ETA_add, ETA_rem) < ETA_base，则将新增SKU分配给aj*，从ai任务中移除，并统一将ai和aj*加入重规划队列，按D-TP的优先级规则处理。
